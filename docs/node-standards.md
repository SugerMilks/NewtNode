# Newt Node Development Standards

## Ideogram Vector

- Display the node as Vector Node in the palette, default title and node help. Keep the internal `vector` type, ports, API routes and saved media stable. Migrate missing/default Vector titles, including automatic numbering and Copy suffixes, while preserving custom titles and historical output labels.

- The main editor entry is **Edit Artwork**. Keep generation controls in the node and local artwork controls in the modal's Layers/Properties tabs. Editor v6 requires `vectorArtworkEditor` before any new edit, saved-look or SVG/alpha delivery operation; never replay writes after an uncertain response. Older drafts and results are retained.
- `vectorArtwork.js`, `server/vector-artwork.js` and `VectorArtworkProperties.jsx` own local finishing. Solid palette changes replace matching fill/stroke colors within selection or all artwork, preserving color alpha, gradients, masks and geometry; respect locks and never use generative color correction. Affine rotation/flip, alignment and even-gap distribution use shared image-space transforms and atomic history steps. Align a single selection to the canvas, multiple selections to their combined bounds; distribute requires three objects. Bound alignment to 32 objects and palette display to 64 colors.
- Box selection intersects visible sibling bounds (up to 128 per level); Shift/Command adds. In the normal selection tool, Shift-drag temporarily draws an additive box without moving selected artwork. Use a four-screen-pixel drag threshold so Shift-click still toggles a single element; explicit resize handles retain Shift free-resize. Snapshot additive intent at pointer-down, clamp the box to artwork, respect the current isolated group, hidden/locked objects, zoom and pan. Clicks and boxes share the ordered selection queue; never discard an earlier in-flight click merely because a drag begins. Escape, blur or pointer cancellation discard the active box without changing selection or closing the modal. Double-click a selected group to isolate its children, Escape or the breadcrumb exits. Keep isolated content during live drag previews. Optional snapping defaults off and compares canvas/neighbor edges and centers, with visible guides and Alt bypass. The standard selection tool exits box/pan mode. Undo/redo cannot interrupt pending fit/alignment operations or reach the node canvas.
- Add Text creates actual SVG text, with local font, weight, size, spacing, line height, alignment and color. Existing generated outlines remain outlines: Replace with Text explicitly hides chosen unlocked originals and adds a new text object, not destructive OCR or font reconstruction. Edit only Newt-created text through the text form; preserve custom names. Escape text through the structured SVG tree, bound to 2,000 characters/30 lines and numeric limits, and never embed/download font binaries. SVG fonts can substitute on another computer; PNG retains rendered appearance.
- Text controls preview valid changes immediately in detached SVG image context, including font size and multiline spacing. Keep the last valid preview while a field is empty or invalid. Draft typing makes no requests/history entries; Apply Text creates one undoable edit and Cancel or leaving the form discards the preview. Scope drafts to the source/document revision and selection, not transient inspect object identity. Block transforms, layer history and exports while text is being previewed so uncommitted pixels cannot be exported as saved artwork. Preserve parent transforms, viewBox mapping, isolation, escaping and original outlines; revoke draft blobs on replacement/close.
- Fit Canvas is explicit, local and one undo step: inspect visible alpha at native resolution, add 0-1,024px padding, and preserve original viewport clipping, hidden objects/resources and source assets. Reject relative dimensions, root clipping/masks, collapsed transforms and oversized/empty results instead of guessing. New dimensions remain within 16,384px/64MP.
- Compare saved versions in a lazy 2/4-up modal, with rename, approval marker and Use Version. Approval is metadata only, not a generation/export trigger. Exclude unsaved drafts; choosing a version uses the normal selected PNG output. Keep scene/project ownership and narrow-screen scrolling intact.
- Saved looks retain only design settings, lettering, palette, font/layout guides and look-only Mood Board references, never brief text, outputs, draft edits, credentials or jobs. `vectorDesignLooks.js` owns the allowlist and `server/vector-design-looks.js` owns up to 100 local looks. Copy bounded passive PNG/JPEG/WebP references into managed look storage so deleting a project cannot invalidate the library. Deleting a library entry retains reference files already applied to projects. Live Mood Board connections take priority, saved references remain visible/removable, and all guides still share the five-reference limit. No automatic generation or AI call occurs. Workflow packages recursively carry applied look URLs; the library itself stays local.

- Font Reference's typeface picker uses the 77-family Mac catalog in `vectorFonts.js`, grouped by Sans Serif, Serif & Slab, Script & Handwritten, Display and Monospace, plus three generic system defaults. List only faces that successfully load through CSS `local()`; `document.fonts.check()` is not an availability test. Do not bundle, download, expose or transmit installed font binaries or request unrestricted font enumeration. Register only the selected temporary face and remove it on replacement/close; cancel discovery when the dialog closes. Saved samples remain PNGs, not font-dependent documents. Other platforms retain available named fonts, generic defaults and explicit custom-file imports.
- The main Vector preview and each saved-variant thumbnail drag through the shared full-resolution image payload, retaining SVG/alpha metadata. Stop pointer-down propagation so media drags cannot move the node. Child thumbnail images must not start a separate native URL drag; ordinary clicks still select variants. Dragging a thumbnail exports that variant without changing selection or starting a generation. Disable dragging for a result with unsaved layer edits until it is saved; other saved variants remain draggable. Font/layout guidance thumbnails are not generated output variants.
- Clicking a generated Vector thumbnail focuses it. Delete/Backspace removes only that selected variant from the node, never its files, History or copies elsewhere on the canvas. Confirm before discarding its unsaved artwork draft; retain other drafts, settings and jobs. Keep the next/previous thumbnail focused (or the empty strip after the last deletion), clear the output when empty, and consume the shortcut locally so it cannot remove a node or wire. Ignore held/modifier shortcuts and deletion while saving artwork or a modal is open; text fields and artwork-editor shortcuts keep their own behavior.
- Text to vector exposes compact Font Reference and Draw Layout controls next to Lettering. `vectorGuidance.js` owns role ordering, normalization and limits; `vectorGuideMedia.js` renders local PNG guides; the lazy native-modal `VectorGuidanceDialog.jsx` reuses Image Edit's mark renderer. Font sample images and locally decoded TTF/OTF/WOFF/WOFF2 files are bounded to 10 MB; image decoding is bounded to 24 megapixels. Only the rendered PNG is uploaded through managed asset storage, never a font binary. Font influence is not guaranteed font reproduction; saved specimens remain usable without the font, but rerendering custom text requires choosing the font again.
- Layout drawings retain normalized editable strokes, dimensions and optional local background URL in node data. Support pen/eraser/line/rectangle/ellipse/arrow/text, colors, size, opacity, undo/redo, clear and zoom. Bound layouts to 500 marks/20,000 points; save a white-backed PNG without cropping the optional underlay. Reopen/copy/package must preserve marks and remap every guide/underlay URL. Do not persist blob URLs or arbitrary filesystem paths. Cancel/failed saves retain previous guidance; late local saves must not cross a project scope.
- The layout is first/primary when enabled, followed by subject references, font sample and dedicated Mood Boards. Include ordered prompt roles: sketch placement/proportions/shapes, font letterforms only, board look only, with authored wording authoritative. Do not reproduce sketch labels or sample alphabets automatically. All references share the existing five-image limit, prompt budget and estimate; toggles exclude a guide without deleting it, and Vectorize ignores both guides. Applying guidance never generates or calls an LLM; generation snapshots the prepared images/prompt and completion preserves later guide edits. Use the existing upload and Vector APIs without new provider parameters or a backend restart.
- Vector settings and input rows are always visible; ignore legacy `settingsOpen` values. There is no Settings accordion, aggregate input dot, result-count/dimensions row, SVG/PNG/Alpha download button row, reference-format footer or model caption. Preserve the thumbnail strip, Layers editor button, generation controls and real port anchors. Saved SVG/PNG/alpha files, layer operations, output connections and project portability remain intact.
- Vector uses a 900px-wide workspace, bounded to the viewport, with a full-width, fixed 2:1 preview area (contain, never crop). Keep thumbnails, Layers/source comparison and the image output in a compact strip below the artwork. Arrange the brief/connections and design controls in two unframed columns, followed by a separate status/generation footer. Stack sections at narrower container widths, keeping labels and guide controls visible without overlap. Match fallback canvas geometry to the wider node; do not alter saved media, settings, ports or project positions during a layout change.
- The compact Vector preview always uses checkerboard and fits the whole image, ignoring legacy `previewBackground` choices. Remove its background/zoom dropdowns and expand icon. Double-click (or Enter/Space while focused) opens the displayed saved image through the shared preview, without starting node drag or canvas double-click actions. Preserve source comparison when connected. Block expanded PNG preview for unsaved layer edits, just like dragging; do not show stale saved pixels as the current edit. The separate Layers editor retains its own background, zoom and pan controls.
- Vector has a dedicated `transferIn` Mood Board input for Text to vector only, with no Style input. Use the compiled, locked board as a look-only image reference; add ordered role instructions distinguishing subject references from palette/shape/linework/texture direction and excluding copied board subjects, logos, lettering and collage layout. Explicit brief, lettering and palette remain authoritative. Boards and subject images share the existing five-reference/10-MB-per-image contract and reference-aware pricing. Keep role labels aligned with upload order; never add provider fields, an extra LLM call or hidden generations. Preserve legacy Mood Board wires on `imageIn` and give them the same look-only role during generation. Vectorize keeps its one original source, ignores dedicated Mood Boards, and disables new `transferIn` connections while retaining saved wires. Keep graph save/copy/preset behavior intact. This uses the existing prompt/image API; no new backend capability or restart is needed.
- Vector's Layers button opens a lazy native-modal editor, with zoom/pan/select canvas and front-to-back hierarchical layer thumbnails. Support Shift/Command multiselect, Alt-click into a group, double-click/F2 rename, visibility, locks, opacity, sibling drag-reorder, delete, manual selection grouping, safe ungrouping, background assignment and undo/redo. `VectorLayersDialog.jsx` and `vectorLayerCanvas.js` own this surface; keep `VectorLayersPanel.jsx` a compact entry/quick-save row. Cancel restores the opening draft; Save Version preserves the original. Close on source/project changes and ignore late work. Never reopen a modal just because a saved `vectorLayersOpen` flag is true.
- On the first explicit Layers opening for an untouched generated result, inspect for a single bottommost, unlocked, fully opaque, uniform canvas-covering path/rect/polygon. Use bounded isolated raster evidence, not names or white-pixel removal; verify visible foreground remains. If certain, assign/name it Background and hide it as one undoable batch. Leave gradients, partial/complex backgrounds, locked art, prior drafts and edited versions alone. Persist `vectorLayersPrepared` on the source result, including a no-candidate review, so Undo/Cancel/reopen never reapplies the automatic change. Capture the Cancel baseline at the Layers click, before lazy loading/inspection. Preview edits only; originals remain untouched and Save Version publishes PNG/SVG/alpha. `server/vector-background.js` owns detection, `vectorLayerOrganization.js` owns setup metadata and folder planning; editor v4 requires `vectorLayerOrganization` health.
- Layers also performs a one-time local Text/Background grouping review, tracked separately by `vectorGroupsPrepared`. Group actual text objects, explicitly labeled lettering/glyph paths and assigned/labeled background shapes; never infer unlabeled outlined letters or background pixels from color, prompt or geometry. Preserve existing folders, locked/hidden ancestors, hidden text, transforms and paint order. Only adjacent same-role siblings may share a folder, including singleton folders; separated runs get numbered names. Transfer all-hidden background visibility onto its folder so its eye and Background switch restore the contents; preserve mixed child visibility. Explicitly labeled backgrounds may be grouped but only the independent raster-proof setup may hide a background automatically. Append the bounded automatic operation to existing drafts, combining first-open hiding and grouping into one undo step when both apply. Older edited results get grouping without resetting background choices. Persist the review even with no candidates, and retain it after Undo/Cancel and Save Version. Require editor v5 / `vectorLayerAutoGroups` health; no AI calls, paid naming or image generations are involved.
- Expose Group/Ungroup commands and Cmd/Ctrl-G / Cmd/Ctrl-Shift-G. Manual Group uses `mode: selection`: accept non-adjacent layers and ordinary nested folders, normalize selected descendants under their selected ancestors, and gather them in existing paint order at the frontmost selected branch of their nearest common parent. This deliberate action can change overlaps; explain the placement in its tooltip and keep it one undo step. Compose pure intervening transforms; never extract children across inherited paint, clipping, opacity, visibility, shared resources, or locks. Report the reason when grouping is unavailable. Share selection eligibility between frontend/backend and gate new drafts with `vectorSelectionGrouping`; legacy/default and automatic grouping remain adjacent-only with unchanged stacking. New groups enter inline rename, remain visible in paginated lists, and show folder icons/counts and expand/collapse controls. Organize groups only adjacent loose top-level objects, separating actual text from artwork and preserving existing groups, hidden/locked/background layers and paint order. It is local organization, not semantic AI segmentation; use neutral unique folder names and one undoable, bounded, non-nested batch. Ungroup can distribute pure transforms with shared affine math; inherited paint/compositing/resource attributes still require the group to remain intact.
- Canvas Shift/Command/Ctrl-click toggles individual selections and a modified click on empty space retains them. Process asynchronous canvas picks in click order; invalidate pending picks after a newer layer-list selection, document/isolated-root change or edit, not after each selection result. Shift-click in the list selects sibling ranges; across folder boundaries it adds the target without discarding prior choices. Cmd/Ctrl-click toggles individual rows; Cmd/Ctrl-Shift adds a sibling range. Reveal canvas selections and new folders without losing pagination or existing expanded folders.
- Selected unlocked Vector artwork moves by dragging its canvas bounding box and resizes through eight handles. Corners preserve proportions unless Shift is held; Alt resizes from center, side handles affect one axis, arrows nudge one image pixel (Shift: ten). Keep zoom/pan independent, cancel active gestures on Escape/pointer cancellation/blur, and record one history operation per gesture. Render pointer previews locally without network calls; validate once on release. Preserve the local preview until the validated result arrives. Use shared `vectorLayerTransforms.js` with `transformation-matrix` for SVG parsing and coordinate conversion, including viewBox letterboxing, root transforms and nested groups; normalize ancestor/child selections to avoid double movement. Preserve clipping/resources/alpha and reject locked descendants, singular parents, nonfinite/extreme transforms and flips. Do not rasterize editable geometry or modify original assets. Require `vectorLayerTransforms` health for editor v3, including restored drafts; this extension needs a backend restart.
- Give the Layers entry a clear button surface, border and hover/focus states. Reserve padding plus a stable scrollbar gutter beside layer-row icons, including overlay-scrollbar platforms; keep header/tools outside the scrolling list. Popup history shortcuts are scoped to the top native modal: Cmd/Ctrl-Z undo, Cmd/Ctrl-Shift-Z and Ctrl-Y redo. Menus/sliders/switches route history to layers; text entry retains native text undo. Recover lost focus after rename/delete without letting shortcuts reach graph history. `vectorLayerHistory.js` owns shortcut classification and bounded history steps; rapid repeats must not append undefined operations or cross a save/project scope.
- `server/vector-layers.js` validates before/after edits, retains resources, limits editing to 5,000 objects and 500 flattened operations, and uses stable SVG IDs. Batches are atomic history entries, limited to 100 non-batch operations and the same total/serialized bounds. Locks protect descendants and structural edits on containing groups; visibility remains independent. Reorder within the original parent; reject ungrouping when group attributes carry appearance/positioning that cannot be redistributed without changing pixels. Local editing may delete all shapes, but provider SVG validation still rejects empty generations. Persist lock metadata on each result and retain it during local saves.
- Canvas picking and selection outlines use bounded alpha rasterization of isolated, server-validated SVGs, with binary paint-order search and a bounded cache. Detached XML is never inserted into HTML; preview/thumbnail SVGs use image/blob URLs only. Keep clipping, inherited opacity/transforms and resources. Limit visible layer thumbnails and paginate large trees. Do not infer semantic layers or remove pixels by color.
- Existing SVG titles/IDs and neutral shape names are free. Auto Name Layers is an explicit, confirmed, optional paid action: one bounded contact sheet for at most 32 unlocked layers, one call through existing vision-provider routing, usage recorded even on invalid output, no automatic retry. Validate returned keys/names and show editable suggestions before applying one undoable rename operation. It must never modify geometry, regroup artwork, or generate images. Require `vectorLayerEditor` health for editor v2 and naming routes.
- Save Version and Save Selection create new managed SVG/PNG/alpha-matte assets at the SVG's original dimensions, retaining the original. Selection isolates chosen objects at their existing canvas positions, preserving inherited transforms, clipping and opacity; unselected objects remain hidden in the editable SVG. The matte is white opaque, black transparent, gray partial opacity. A PNG with an alpha channel can still be fully opaque if its background remains visible. These operations cost zero and never call a provider.
- Persist per-result layer drafts with source URLs as values for recursive package remapping. Unsaved edits affect only the local preview; save before dragging/publishing changes. Saved variants use the normal canonical PNG output, with `svgUrl`, `alphaUrl`, source SVG and background IDs retained through copy/save/import. Local save completion merges into current node data, preserves active generation receipts and intervening selection, and never crosses a project scope. Require `vectorLayers` health for the local inspect/save routes; no request fallback or replay.
- Vector (`vector`) is a dedicated graphic-design node, beside Image Model, using the enabled Fal credential only. Text to vector uses `ideogram/vector/text-to-vector`; Vectorize image uses `ideogram/vector/image-to-vector`. Keep Ideogram 4.5 limited to Image Edit and preserve Image 2.5 and other model selections. Vector stays manual-only for Run All and Newt until paid-request journaling/budget support is explicitly added.
- `src/ideogramVector.js` owns settings, prompt composition, validation and published estimates; `VectorNodeBody.jsx` owns the compact UI. Text generation supports a local design brief, optional connected prompt, visible graphic brief presets, up to five references (10 MB each), quality Low/Medium/High, documented aspect ratios and optional seed. Vectorize requires exactly one JPEG/PNG/WebP (50 MB maximum) and uses Fal's `default` or `simple` detail mode. Never send direct-Ideogram-only enums or invent palette, font or transparency parameters. Settings changes never generate or discard outputs.
- Vector's Generations selector supports 1-6, defaults to 1 for new and legacy nodes, and persists as `batchCount`. Snapshot the complete prompt/settings/references at Run, then submit one saved variant at a time through the existing single-output API, with an independent request receipt and per-output History charge. Fixed seeds advance by one, wrapping within the supported range; blank seeds stay random. Display the batch-total estimate only when API Cost is enabled. Preserve completed results, later settings edits and manual result selection. A failed/uncertain response, Stop Waiting, unmount or project change stops the remaining queue; read-only Check may recover only the current receipt, never resume paid work. No backend contract or restart changes are required.
- Canonical results use `type: image` with a managed PNG `url` for existing Preview/downstream/Output compatibility and a managed, sanitized `svgUrl` for editable SVG artwork. Keep the original shape geometry, both files and per-result settings through variant selection, copy, save, import and recursive workflow packaging. SVG files remain in managed project output storage; ordinary Output Original continues exporting the canonical PNG. Do not rasterize away the only editable original.
- `server/vector-svg.js` validates a bounded passive SVG allowlist before rendering or persistence. Reject executable/embedded content, external resources, DTD/entities and unsupported active features; preserve supported paths, groups, transforms, clips and gradients. Preview only in image context, never inject provider SVG into HTML. Serve SVG media with restrictive CSP and nosniff headers. Unsafe/malformed output is a failed delivery, never an automatic regeneration.
- `server/ideogram-vector.js` and `server/routes/ideogramVector.js` validate before upload, use a captured single-submission Fal client, deduplicate request IDs and save project-local SVG/PNG plus History. Private receipts under ignored `server/data/ideogram-vector/` persist intent, provider request IDs and credential fingerprints, never keys. The read-only status route recovers submitted/completed work without generating; require the original enabled key for provider status. Browser API calls require `ideogramVector` health and never replay paid POSTs through fallback. Stopping waiting does not guarantee provider cancellation or avoid a charge; completed server work remains in History. Reopen/copy must not resubmit interrupted work or accept late results into a different project.
- Published estimates verified October 26, 2026 are $0.13/$0.16/$0.20 for Low/Medium/High prompt-only SVGs, $0.32 for High with references, and $0.10 per image vectorization. Use shared request-specific estimates with provenance, honor API Cost visibility, and retain recorded History amounts in Stats. Public docs and mock tests do not establish account entitlement or live output quality. See [Ideogram Vector workflow](ideogram-vector.md) for official sources and verification.

## ReFrame

- ReFrame (`cameraCoverage`, formerly Camera Coverage) sits beside Camera in the node menu. It accepts one master image and outputs the selected saved shot/version; Preview receives every original, refined and upscaled version with stable shot/version identity. Preview selection must update the shot's selected version as well as its result URL. Keep it separate from Utility Coverage, which creates independently prompted images. ReFrame is manual-only for Newt and Run All.
- ReFrame is a display-name change. Keep the `cameraCoverage` node type, data keys, ports, API routes, capability flags, receipt paths and module filenames stable. Migrate only missing/default Camera Coverage titles (including automatic numbering/Copy suffixes) to ReFrame; preserve custom titles, media, connections and pending jobs. Historical records retain their original labels; new records use ReFrame.
- Fal H3 Max Camera Controls (`minimax/h3-max/camera-controls`) generates a frozen-scene video along an explicit trajectory. It is not a Gaussian-splat reconstruction or an exact 3D camera. The Three.js diagram shows requested poses only. Preserve the first master pose, bounded orbit/elevation/distance, disabled prompt expansion, and the shared frozen-scene prompt. Defaults: Orbit, Coverage preset, 10 seconds, 768P. Do not promise identity, unseen geometry or precise shot classifications.
- Fal's public OpenAPI (rechecked October 26, 2026) limits a trajectory to 12 keyframes, each with only time/azimuth/elevation/distance. Orbit supports 2-8 requested positions; budget holds without exceeding 12 or dropping positions. Straight Travel supports 2-4 positions, converting bounded Slide (X), Boom (Y), and Dolly depth (Z) into spherical keyframes. Spend remaining keyframes adaptively on straight XYZ segments to reduce spherical-interpolation curvature. Keep the master at (0,0,1), use relative units rather than meters, and preserve depth/height on lateral slides. This is approximate subject-tracking travel, NOT independently controlled fixed-heading translation. Never invent translation/orientation API fields or silently substitute image-to-video. Explicitly selected travel uses the same Fal camera endpoint and pricing.
- Straight Travel offers Slide Coverage, Boom Coverage, Dolly Coverage and Custom Travel presets. The diagram shows linear rails/path and retains subject-facing camera orientation; diagram distance is proportional to the provider distance. Changing modes resets only the requested path, not media. Persist mode on passes/shots and private receipts. Require `cameraCoverageTravel` backend capability before new travel or 7-8-position requests so older backends cannot silently misinterpret paths.
- Protect Framing is opt-in/off by default, preserving existing paths and intentional close coverage. Extra Room defaults to 20% (0-40%): after the fixed first pose, constrain requested Orbit distance or Travel depth to at least `1 + room/100`. Preserve larger distances and Travel slide/boom coordinates; never scale the whole lateral path. The control is a camera-distance allowance, not a measured image margin or subject detector. Use the same `coverageFramingPoses` transformation for displayed pose controls/diagram and server trajectory; preserve raw poses for toggling off. Add explicit subject-extent/headroom/group-composition guidance without changing identities, staging, existing intentional crops or inventing provider fields. This reduces inward-crop risk but does not guarantee model framing, restore missing source content or fix prior outputs. No extra analysis/generation calls. Gate enabled protection on `cameraCoverageFraming`; persist snapshotted settings, effective poses and actual trajectory in receipts/History, passes and captured shot metadata. Disabled requests retain their legacy fingerprint.
- Scrubbing and frame extraction are local. Use full-resolution FFmpeg PNG extraction, not screenshots of the video element. Preserve passes, selected frames, shot names/order and immutable versions in node data and workflow packages. Removing shots never removes local files. Favorite/duplicate shot controls are not shown. Shots and the monitor drag through the shared full-resolution media helpers, using the displayed version; completed refinements/upscales become the selected version unless the user selected another version while the request ran. Existing media helpers carry canonical result items to Preview, Output, History and the project output rail.
- Auto Refine is visible outside Settings and on by default. An explicit capture saves the original first, then submits exactly one refinement; no effects, reopen, copy or recovery may auto-generate. Failed/disabled refinement preserves the original and reports the issue. New/missing model defaults are Nano Banana 2.1 at 2K; preserve explicitly saved model choices and Auto Refine off. Manual Refine remains available. Capture settings and the source version are snapshotted before the asynchronous operation.
- Upscale uses Fal Topaz High Fidelity V2 with face enhancement and cropping disabled. Refine reuses enabled image-model routing with the captured shot as sole composition authority, not the master camera view. Both are separately billed operations retaining the original. Honor API Cost visibility; H3 estimates use the published post-promotion per-second rate, while Topaz is unknown until a settled charge is available.
- Per-shot Lens controls offer Original (no edit), 8mm Fisheye and 18/24/35/50/85mm rectilinear full-frame-equivalent creative targets, plus Keep Camera Position (default) or Keep Subject Size. Only the explicit Change Lens action submits one paid image edit through the existing enabled refinement model/size/provider route. Nano Banana 2.1 remains the default, with saved model choices preserved. Fixed camera changes FOV without dolly/parallax; subject-size matching permits axial travel and resulting perspective changes, preserving world-space blocking. The source focal length is unknown: never assume 50mm, claim calibrated optics, warp a bitmap, modify H3 keyframes, or mix lens-changing instructions into normal Refine/Auto Refine. Every lens edit uses the shot's first clean refinement as its sole reference, regardless of selected version; fall back to the original capture without automatically generating a refinement. Trace version IDs/URLs to exclude lens edits and their refined/upscaled descendants, including older versions without inherited lens metadata. Untraceable legacy refinements are eligible only before the first lens-marked version; broken/cyclic ancestry is ineligible. Use the stable base's dimensions for aspect ratio and price estimation. Preserve identity, props, lighting and grade, and infer unseen areas conservatively. Controls/tooltips describe an AI approximation, not a fidelity guarantee.
- 8mm Fisheye has dedicated curvilinear-projection guidance, not the rectilinear branch's straight-line/no-fisheye instructions. Request coherent edge curvature, retained identity/underlying anatomy, and a frame-filling rectangular result without black circular borders. Label it explicitly in the menu, version and History title; save requested `projection: fisheye` metadata (other new lens edits use `rectilinear`). Both framing modes remain available. Subsequent Refine/Upscale preserve the lens metadata and intended distortion, never automatically de-fisheye the result.
- Lens preferences live on each shot (`lensTarget`, `lensFraming`) independently of the displayed version. Original leaves that displayed version unchanged; use Shot version to restore an earlier image. Snapshot lens/framing/model/source before submission; save a labeled immutable `kind: lens` version with `sourceVersionId`, source URL, model, cost and approximate requested-lens metadata. Snapshot the displayed version separately from the stable source so completion selects the result unless the user chose another version while it ran. Preserve originals, user navigation and newer settings. Refine/Upscale still use the selected version and inherit its lens metadata. Publish and drag lens versions through the same Preview/Output/media path as other images. Dropdown changes, reopen, copy and capture must never auto-run lens edits.
- Background work must not lock the entire node. Keep one camera pass receipt (`coverageJob`) and independent per-shot refinement/upscale receipts (`coverageShotJobs`); reject overlapping operations/deletion on the same shot while permitting other shots, browsing, local captures, names/order and next-pass settings. Persist intent synchronously before paid calls and merge completions into current data, not the submission snapshot. Capture releases its local extraction lock before Auto Refine. Completed passes append without switching the monitor/current pass and offer an explicit view-new-pass action. Delayed captures also respect intervening navigation. Job errors remain scoped to their own receipt; another successful job must not hide them.
- Each shot thumbnail shows a small non-interactive spinner only for its own submitting, queued, running or saving refinement/lens edit/upscale. Keep thumbnail dimensions, selection and dragging unchanged; expose the action in its accessible label/tooltip and busy state, and respect reduced motion. Completed, failed, uncertain and interrupted jobs do not spin; a camera pass does not mark existing shots as busy.
- On reopen, durable pass/upscale receipts can be checked independently without another POST; an interrupted submitting receipt becomes uncertain and remains manually checkable. Refinements become interrupted with a History warning and require explicit release before rerunning that shot. Copies/imports drop all active jobs. Migrate legacy single-upscale `coverageJob` and `coverageEnhancing` without losing receipts or media. Never auto-retry failures or let a late response from an unmounted/released job overwrite current work.
- Lens edits use the same per-shot lock and non-replay image-job lifecycle as refinements. Never poll a lens job against the H3 receipt route or allow a live image request to be released as if it were a durable pass. Failed/interrupted lens edits retain existing media and require checking History and explicit release. Other shots and camera passes remain usable. No backend restart or new billing integration is required for lens editing.
- `server/camera-coverage.js` stores private receipts under ignored `server/data/camera-coverage/`. Persist intent before a single guarded paid queue submission; never retry an ambiguous POST. Recovery checks only the originating request and enabled credential fingerprint. Persist the provider URL before download, and deduplicate History. This explicit queue lifecycle replaces `subscribeFal` for this recoverable operation only. Do not add a local generation deadline. Copies/imports clear active jobs; reopening can read status but never generates. Image refinement uses the existing no-replay image route and interrupted refinements require checking History.
- `CameraCoverageViewport.jsx` owns a full-width Three.js pose diagram with a textured master, camera/lens, orbit/elevation guides or straight travel rails. It is not a reconstructed scene. Keep the original Camera node's viewer unchanged. Support pointer and keyboard pose editing, narrow layouts, fixed master and disposal of WebGL resources.
- Keep the implementation in `src/cameraCoverage.js`, `CameraCoverageNodeBody.jsx`, `CameraCoverageViewport.jsx`, `useCameraCoverage.js` and `server/camera-coverage.js`; NodeEditor only wires catalog/config/defaults/normalization/connections. Gate calls on `cameraCoverage` health and keep paid tests opt-in. See `docs/camera-coverage.md` for the workflow, limits and test commands.

## Persistence Standards

Saved workflows are long-lived project files. Changes must avoid breaking them.

- First launch without a valid draft and New Project start with an empty graph (no nodes, edges or groups) at the default viewport. Never insert a starter workflow automatically. Restore existing drafts, including intentionally empty projects, as saved; loading a saved workflow or explicitly inserting a preset remains unchanged.
- New Project, Save, Save As, Open, and Import as Canvases live under the left toolbar File menu. Open replaces the current project; Import adds the selected project's canvases to the open project with new IDs and cleared copied runtime jobs.
- When a workflow replacement would discard unsaved graph or project-name changes, prompt with Save, Don't Save, and Cancel. Save writes never-saved workflows to the local app saved-workflows folder.
- `workflowChangeGuard.js` keeps one pending replacement. Save keeps the dialog visible with disabled actions until the write succeeds; failures stay inline with retry/cancel choices. A second navigation or double click must not replace the pending target or launch a duplicate save. Save uses the latest editor state, and newly arrived graph changes must be saved before leaving. Cancel/discard never submit a save. Unmount cancels the pending replacement, not a filesystem write already in progress.
- Ctrl+S and Cmd+S save the current workflow. If it has never been saved, use the default local saved-workflows registry rather than requiring Save As.
- The Recent workflows dropdown behaves as a Recent Files list backed by the local server registry, not as a live scan of every JSON file on disk. The trash action removes the workflow from the dropdown only; it must not delete the local registry JSON, packaged workflow JSON, or external workflow JSON from disk. Re-saving or re-opening a workflow can register it in the dropdown again.
- Save/Open/Import orchestration belongs in `src/useWorkflowPersistence.js`; workflow document construction and display paths belong in `src/workflowFiles.js`; graph fingerprints, cloning, deduping, import remapping, and stale runtime cleanup belong in `src/workflowState.js`.
- Projects contain one or more named canvases. `projectCanvases.js` owns normalization, storage graph construction, canvas-scoped replacement and copy/move. Store all nodes/edges/groups in one project graph; nodes and groups carry `canvasId`, and `graph.canvases` records ordered `{id,name,viewport}` descriptors. `activeCanvasId` and the legacy top-level `viewport` record the open canvas. Old graphs migrate into Canvas 1 without changing node IDs or saved media. New multi-canvas documents are version 2.
- Save and Save As include every canvas and all of their assets, never only the visible graph. Backend save/list/open/package paths must retain this metadata. Require health `projectCanvases` before a new client submits a multi-canvas save; reject legacy saves over a version-2 project.
- Switching canvases hides/inerts node cards without unmounting running jobs. Pause media playback, clear selection/wire gestures, restore that canvas's viewport and undo stack, and remeasure ports. Undo merges only its canvas so another canvas's completed job survives. Canvas deletion requires confirmation, rejects working canvases and the last canvas, and removes no local files. Moving selections disconnects only cross-boundary wires with confirmation; copying assigns fresh IDs and clears jobs/automatic exports. No wires cross canvases. Newt's graph/actions stay scoped to the canvas containing Newt, even while the user works elsewhere.
- The asset drawer can show Canvas or Project assets, including uploaded media; reusing an asset creates a local media node, not an inter-canvas dependency. Presets insert into the current canvas; capture uses that canvas or its selection.
- The dirty/unsaved fingerprint includes nodes, edges, groups, canvas names/order, project name, and package path. It intentionally excludes active canvas and viewport pan/zoom.
- Add normalization for new node fields.
- Preserve unknown data fields when normalizing unless they are unsafe runtime state.
- Migrate renamed node types or ports.
- Clear stale `running` state on load.
- Keep `resultItems`, `resultUrl`, and selected result indexes compatible with existing workflows.
- Store reusable assets under `public/models` or `public/models/poses` only when they should be versioned with the repo.
- Store unpackaged generated outputs under `/outputs/<workflow-name>/`, unpackaged uploads under `/uploads/<workflow-name>/`, unpackaged helper dependencies under `/outputs/<workflow-name>/dependencies/`, and registry copies of saved workflows under `/saved_workflows`.
- Treat `/saved_workflows/inputs`, `/saved_workflows/outputs`, and `/saved_workflows/dependencies` as local app storage for copied/generated assets. Keep those media files ignored by git; only `.gitkeep` placeholders should be tracked.
- Treat `server/data/*.json`, including `recent-workflows.json` and index files, as local runtime state. These files should be ignored by git and never used as source fixtures.

## Workflow Package Standards

Portable packages are the default Save As shape for workflows that need to move between machines or live on a shared drive.

- Save As opens the native folder picker and lets the user choose the parent folder.
- Save As creates or updates a package folder named from the workflow, with this shape:

  ```text
  WorkflowName/
    WorkflowName.json
    inputs/
    outputs/
    dependencies/
    .newtnode/
      manifest.json
  ```

- `inputs/` contains uploaded source media used by graph nodes.
- `outputs/` contains generated media and explicit node outputs.
- `dependencies/` contains derived helper assets needed to rerun or inspect the graph, such as padded frames, composed mood boards, masks, and other intermediate support files that are not primary user uploads or final outputs.
- `.newtnode/manifest.json` records package metadata and copied asset entries. It should help diagnose missing assets without becoming required runtime state. Keep the package root visually focused on the workflow JSON and asset folders.
- A packaged workflow should still appear in the Recent workflows dropdown through the local `/saved_workflows` registry copy.
- Save updates the attached package in place. Save As copies the graph and its current local assets into the chosen package folder.
- Once a package is attached, upload and generation requests must include the workflow package context so new files are written into that package.
- Packaged assets must be served through `/workflow-assets/<workflow-id>/...`.
- Vite development proxy config must include `/workflow-assets` anywhere it includes `/uploads` and `/outputs`.
- Opening a packaged workflow must register its package path with the local server before packaged assets are expected to preview or run.
- Importing a workflow must remap node, edge, and group IDs and place the imported graph in a clear canvas area rather than directly on top of the current graph.
- Do not use browser-only object URLs or absolute machine-local paths as saved graph dependencies.

## Provider Key Routing

- Fal is the default provider route for remote models.
- Atlas Cloud uses the existing Settings API-key version controls, starting with Atlas Cloud API V1 and allowing one active version at a time. Preserve disabled versions and local-only storage; `ATLAS_API_KEY` remains the environment alternative. Never include keys in workflows, exports, or browser pricing data.
- Supported media routes choose enabled, configured providers in Fal > Krea > Atlas order before submission. LLM routing is independent of media routing; preserve explicit direct-Google behavior and direct ElevenLabs audio routing. Never retry a failed or uncertain paid request automatically or switch providers after submission.
- `src/llmProviders.js` selects the preferred enabled LLM provider, then Fal > OpenAI > Atlas. Preserve text-provider environment preferences; Newt retains direct OpenAI when enabled and otherwise uses Fal or Atlas. Krea's public OpenAPI has no general text/vision LLM endpoint (checked 2026-09-10); skip it for LLM tasks and name the companion-key requirement when Krea is the only key. Never silently replace an OpenAI model with another model or use disabled credentials.
- `server/llm-responses.js` adapts stateless OpenAI Responses requests for Atlas and Newt's Fal Responses route. Retain Astra/Luna choices, reasoning and structured/tool contracts; gateway conversations keep complete tool/result pairs but omit provider-specific item IDs and encrypted reasoning. Capture one key/provider before submission and keep the Director analysis-cache credential consistent with the actual request. Failed, malformed, incomplete and refused answers must not replace scene text or execute agent tools. No automatic paid retry or cross-provider replay. API schemas and mock tests do not establish live account access.
- Atlas LLM token rates for Astra/Luna use `src/atlasLlmPricing.js` and the shared pricing catalog. Validate all eight standard short/long context rows, including Atlas's inclusive 272000 threshold, before updating. Prefer reported charges, otherwise record a provider-specific estimate; unknown charges remain unknown/reserved. Capture rates with the request so later price refreshes do not revalue it. Fal agent charges use reported usage, not direct OpenAI prices. Voice dictation and audio transcription still require the enabled direct OpenAI key; never send a Fal/Atlas key to OpenAI.
- Atlas image support covers GPT Image 2, Image 2.5 Sunburst/Flare, and Nano Banana Pro, including compatible Character, Coverage, Storyboard, and Sunburst Image Edit paths. Preserve variant, masks, references, and quality.
- Atlas video support covers Seedance 2.0/2.5 and MiniMax H3. Exclude Kling from Atlas routing while its reference contract is unverified. Validate provider-specific reference, duration, resolution, mask, and audio constraints before upload/submission; fail unsupported settings without truncation, silent substitution, or paid fallback. Atlas Seedance 2.5 has no `1920p` or native `4k` output option; supported super-resolution tiers are separate choices.
- Seedance 2.5's Video Model `Task` selection defaults to Generate Video (`seedanceTask: reference`, including old workflows). Edit Existing Video (`edit`) is opt-in and uses the same model and reference-to-video endpoint. The [Atlas schema](https://www.atlascloud.ai/docs/more-models/bytedance/seedance-2.5-reference-to-video/generateVideo) verified October 6, 2026 requires `omni_reference_task_type: edit`, `duration: -1`, and `ratio: adaptive`. The [Fal schema](https://fal.ai/models/bytedance/seedance-2.5/reference-to-video/api) uses `task: editing` and auto duration/aspect. Support one locally probed 4-30 second source video, optional reference images/audio, no Start/End Frames or Director. Do not offer an unverified Krea edit operation, infer editing from prose, change providers, or replay a paid request. Reject unsupported combinations and invalid/oversized references before uploads. Keep original duration/aspect saved while displaying Source video in edit mode; switching back restores them. The health flag `seedanceVideoEditing` prevents new clients silently submitting edits to an old backend. Persist the operation and source duration in History and include task choice in Newt reuse/price keys; display unknown editing cost until a verified prepared-request quote or actual charge is available. Source-matched editing does not promise frame-exact performance, unchanged duration, or improved image quality; Atlas documents possible output shortening. Mocked contract checks do not establish generated quality.
- Video Model reference labels must match the named tags shown in the node, not an uploaded filename when the prompt addresses the node by name. Preserve result labels for unrelated consumers. Resolve named image, video, audio and Character tags to ordered provider references; Seedance 2.5 node requests use documented `@ImageN`, `@VideoN`, and `@AudioN` syntax. Reject unmatched tags before a paid request rather than guessing misspellings or binding them to another asset. Existing media and user-authored prompts remain unchanged.
- `src/atlasImages.js` and `src/atlasVideos.js` own request contracts; `server/atlas.js` and `server/atlas-media.js` own transport and managed-media integration. Public schema/catalog checks and mocked tests do not establish live account/model access or output quality. No paid generation or live API-key test was performed for this integration.
- New Image Model nodes default to Nano Banana Pro with the existing `16:9`, `2K`, single-image settings. Creation uses the shared node default and falls back to an enabled model if Pro is disabled; preserve explicit saved/preset selections and legacy missing-model restoration. Do not change Coverage, Storyboard or Utility defaults with this preference. Legacy image-generation fallbacks retain `16:9` and `1K` when dimensions are absent.
- `videoDefaultModel` is Seedance 2.5 for new Video Model nodes and new Frame It video choices; Director's existing 2.5 scene defaults remain unchanged. Put 2.5 first in the video catalog and use it for the all-disabled preferences safeguard. Fresh Video Model creation respects enabled models and Newt's explicit favorite overrides. Preserve saved selections, preset models, legacy missing-model restoration, duration/resolution/aspect/audio settings and provider routing. Draft and editing remain opt-in; Seedance 2.0 stays available.
- Google image models should use a direct Google API key only when `GOOGLE_API_KEY` exists. When it is absent, route the same Google-branded image model through Fal instead.
- Do not automatically fall back from direct Google to Fal after a Google request fails; if the user supplied a Google key, Google model failures should surface as Google failures.

Its ignored `node_modules` stamp tracks the package/lockfile, platform and Node version; missing direct packages invalidate it. Failed installs must stop startup without marking preparation complete. Do not touch runtime settings, keys, workflows or media during dependency preparation. Include both HTML entrypoints and dependency changes in build freshness checks.
- Older VS releases use `credentials`/`activeCredentialIds` rather than `apiKeyVersions`. Migrate only when current versioned keys are absent, retain up to the legacy maximum of 20 keys, and preserve the exact active selection or disabled state. Keep the original records in local settings. VS main release synchronization preserves both Git ancestries and a backup branch, never force-resets other users' clones. The older Settings updater only pulls source; the first upgrade requires a launcher relaunch to install dependencies and rebuild.

## UI Design Standards

- The canvas is the primary workspace, not a landing page.
- The node palette's File, Recent Projects and Preset Workflows dropdowns share an opaque near-black (`#080808`) surface with a subtle contrasting border, distinct from the palette controls behind them. Preserve readable labels, hover/focus states and existing menu interactions.
- Canvas tabs use compact content-sized pills without separate three-dot buttons. Clicking an inactive tab only selects its canvas and closes open tab menus; clicking the active tab toggles an options menu anchored directly below that tab, clamped within the toolbar and repositioned on scrolling/resizing. Preserve double-click/F2 rename, right-click menus without changing canvases, drag reordering and arrow-key canvas navigation. Down Arrow opens/focuses the menu; Escape closes it and returns focus to its tab. Add/Find Canvas and Show project outputs dismiss any tab menu.
- Reorder canvases by dragging their tabs, with a placement marker and edge scrolling for overflowing rows. Remove Move Left/Move Right menu items; Alt+Left/Right provides a keyboard equivalent. Only a valid drop commits the new order; Escape/outside drops leave it unchanged. Reordering never switches the active canvas, alters its nodes, or opens a tab menu. Preserve order in project saves.
- When the project output drawer is collapsed, its Show project outputs icon sits directly after Add Canvas and Find Canvas in the canvas tab toolbar, sharing their size and vertical alignment. Opening it closes tab menus, preserves selection and does not start a canvas gesture; the drawer retains its own Hide project outputs action. No output-drawer control floats in the canvas corner.
- The app opens directly to Projects. Top navigation contains only Projects, Stats and Settings; individual canvases within projects retain their canvas labels. The standalone Image/Video pages, their generation forms and page-only model aliases are retired. Keep the internal `nodes` workspace key and the node editor mounted while other tabs are active so unsaved work and in-flight node tasks survive tab changes. Preserve local draft restoration, node/provider preferences, generation chimes, diagnostics, image context menus, Stats history (including older standalone runs), backend media APIs and all image/video nodes. No media or saved projects are deleted by this UI cleanup. Check the full shell with `scripts/verifyWorkspaceNavigation.mjs`, which uses an isolated browser and mocked APIs.
- Canvas selection gestures (marquee, node/group selection, selection dragging, and edge selection) transfer keyboard focus to the canvas without scrolling. Suppress the browser focus outline only on the canvas container; preserve its normal border, node/edge selection highlights, and focus indicators on child controls. Keep Delete/Backspace protected in text/editable controls and while modal dialogs are open, for both nodes and connections; honor consumed keys and IME composition. Keyboard routing lives in `src/nodeKeyboardRouting.js`; the isolated `test/browser/canvas-focus.html` harness checks focus appearance and shortcuts without project access.
- Node cards should be functional, compact, and scannable.
- Controls should be familiar: sliders/inputs for numbers, toggles for booleans, selects for option sets, icon buttons for compact actions.
- Text must fit inside buttons, rows, cards, and panels at desktop and mobile widths.
- Avoid one-off color themes. New media colors must be distinct from existing node categories.
- Do not add decorative orbs, oversized hero elements, or marketing-style sections inside the app.
- For 3D scenes, use Three.js and verify nonblank rendering.
- Use stable dimensions for boards, previews, result panes, and tool rows so hover or dynamic content does not shift layout.
- Scrollable tool panels should consume available space before introducing nested scrollbars. When a control list must scroll, make the scrollbar discoverable and verify the first and last controls are reachable.

## Director and Storyboard Reasoning

- Storyboard is independent of Director. Do not offer or create Director-to-Storyboard connections. On graph load/import/paste/preset insertion, `src/storyboardMigration.js` freezes the inherited active scene and rewires its used Character/location/prop references before retiring the control edge. Preserve rendered panels, versions, nodes and previous input metadata. Keep Director-to-Video behavior unchanged.
- Storyboard planning/revisions/review use `server/routes/storyboard.js`, strict shared contracts in `src/storyboardWorkflow.js`, and the versioned directing policy in `server/storyboard-skills/directing-v2.md`. See `docs/storyboard-workflow.md` for maintenance. Native Auto chooses 1-35 panels from story beats, pacing and optional duration, not a fixed six. Each panel records shot purpose, shot ID/keyframe phase, camera, cast and before/after state; the plan records geography, axis, lighting and prop continuity. Cached visual location/prop analysis is reused only for identical content, instructions and provider credentials.
- The Character input sits directly under Props in Storyboard Setup and is independent of the monochrome Storyboard Style switch. There is no uploaded-character section; new references come from connected Character nodes. Preserve legacy uploaded-character data and prepared sheets for saved-project compatibility. Only custom Style/Mood Board inputs remain gated by the style switch.
- New Storyboards default to Shot List with one blank row. Setup replaces the summary editor with ordered shot rows: description, framing/lens/angle (Auto or explicit), thumbnail, add/delete/reorder, protection and individual generation. `src/storyboardShotList.js` owns row validation, plan constraints and authored-direction provenance. Plan Shots requires 1-35 nonempty rows and returns exactly one panel per row with stable IDs/order and explicit cameras preserved; Auto can be resolved by the planner. Use the same character/spatial/continuity logic and existing QC/revisions. Replanning keeps images/versions, and changed row descriptions/cameras require planning before image submission. A fresh plan's scene signature must include its resolved camera values. Require `storyboardShotList` health capability before a paid planning POST.
- Dialogue, Action, Commercial and Montage retain their summary UI and behavior. Saved `Narrative` or missing approaches retain the legacy Standard summary workflow without automatic conversion; Standard is offered only while it is the current legacy choice. Switching approaches preserves media and authored rows. Shared labels/descriptions live in `storyboardApproachDetails`. Keep summary Auto frame-count planning separate from exact Shot List counts.
- Camera Personality is independent of approach: Restrained, Expressive (default, also for missing/invalid saved settings), or Bold. `src/storyboardCinematography.js` owns shared camera choices, planning policy and rendering guidance. Use the policy in normal planning/revisions and PDF shot-list building, without another LLM stage. Selected/user-scripted cameras outrank personality; revisions retain existing camera intent unless asked to change it. Dutch Angle is supported consistently by schemas, both editors and save/reopen normalization. Preserve existing media/history and never automatically replan when this preference changes. New requests carrying the preference require the `storyboardCinematography` health capability before paid submission.
- Cinematic expression describes a drawable viewpoint, subject distance, scale, depth and graphic composition, not random lens cycling. Keep spatial/cast records consistent with every new view and maintain same-shot continuity. Rendering simplicity must not flatten intended perspective. Both Balanced and Deep QC preserve deliberate distortion, roll, framing and cropping while still rejecting real identity, anatomy, action and occupancy errors. Aesthetic variety alone must not trigger paid retries; the retry ceiling is unchanged.
- Separate Create New Plan (explicit replacement confirmation; protected panels block it), Generate Missing, Regenerate Selected (current directions), and Revise Selected (one to eight panels, synchronized directions and replacements). Never replan automatically because scene text changed. Keep unselected/protected panels intact; report continuity effects outside the selection as advisory warnings. Sequence Review is optional and advisory; do not claim unseen images were reviewed.
- Preserve old images and metadata until a replacement succeeds. Queue/error/status updates must not invalidate the compiled board. Changed images or directions invalidate it. Snapshot up to eight previous image/direction versions and retain them through workflow packaging; internal frame exports must have unique filenames so older versions cannot be overwritten. Restore is explicit and also preserves the displaced version. Reject stale responses after intervening edits, and reset interrupted runtime states without automatically retrying paid work. Do not replay Storyboard paid POSTs through API fallback.
- Storyboard View is an image-first gallery with one expandable panel editor, thumbnail selection and contextual batch-revision controls. Keep per-panel protection; there is no overall lock. Local contact-sheet output preparation is debounced until work settles, guarded against project switches/deleted or changed nodes, and never alters generation status or calls paid models. Reuse legacy compiled outputs; invalidate source signatures on changed images/captions/order/format. Failed image loads must not publish blank panels; show a retryable output-specific error and never loop on failure. Export Frames/PDF uses completed panels directly and does not wait on the contact sheet.
- Storyboard Setup uses compact, consistent left-side controls and a top-aligned scene description, stacking at narrower node widths. The resizable description wrapper owns both the textarea and tag overlay; keep their dimensions, text metrics, padding, scroll offsets and scrollbar gutters identical. Never let grid stretching separate the visible overlay from the editable viewport. Planning Notes starts compact and remains resizable. Scope these layout rules to Storyboard so other prompt editors keep their existing sizing; connected Scene Text stays read-only without replacing the saved local description.
- New Director nodes and added scene tabs share `filmDirectorNewSceneSetup`: Cinematic, 30s, Seedance 2.5, 1080p, 21:9, Auto shots, and Production Sound. Start the first scene at Scene 1 and number additional scenes normally. Apply these defaults only on creation; keep saved choices and legacy snapshot/loading fallbacks intact.
- Director Scene Setup owns `skillApproach`: Cinematic (unchanged default, including legacy scenes), Vintage, Animation, Stop-Motion, Commercial, Music Video, or Montage. `src/filmDirectorApproaches.js` owns normalized choices and approach-specific planning/scene-rule guidance; preserve the choice in each scene, revision snapshot, request and video output. Changing approach invalidates dependent style, camera and shot-list drafts for the normal setup-lock workflow without deleting scene overview or asset connections. Revisions preserve the selected approach unless explicitly changed. Vintage's 16fps/hand-cranked direction and Stop-Motion's stepped 8-12-pose cadence are visual instructions, not API frame-rate parameters. Animation uses coherent animation-medium language; Stop-Motion favors tactile miniature/clay materials rather than interpolated CGI. Commercial uses polished premium advertising language. Montage and Music Video preserve continuity within vignettes while allowing intentional location/time jumps between them. Audio updates and saved-prompt normalization must retain the selected visual scene rules.
- Director `musicIn` accepts one active full-resolution audio file, uses the orange audio port, and follows Scene Setup locks. It is required for Music Video; unused music is not forwarded for other approaches. The active track overrides Production Sound/Silent with a dedicated soundtrack policy, enables generated audio, and is visible in the connected Video node's reference summary. It replaces unrelated audio/Character voice references for this run. Keep the input connected across scene tabs; only the active Music Video scene uses it. Track changes invalidate camera/shot planning through normal lock-aware refresh and retain the other scene text. Preserve `skillDirectorLockedMusicSignature` in scene/revision snapshots.
- Music Video uses Seedance 2.0/2.5 or MiniMax H3 reference-to-video; reject Kling and start/end-frame routes before a paid request because they cannot carry the soundtrack. MiniMax H3 additionally requires a visual reference. Enforce guards on client and server, including after approach/model revisions. Do not promise perfect lip sync or original-audio fidelity from a generative model. `server/director-music.js` performs bounded, local FFmpeg waveform analysis of the opening segment (up to 30 seconds), caching 12 results by file path/size/mtime and analyzed duration. Relative level changes are optional pacing cues, not verified beats, BPM, lyrics or audio understanding. No paid analysis model is added. Keep the actual track as the generator's vocal/timing authority; never invent transcript content or replace/loop missing music.
- `server/creative-llm.js` owns GPT-6 Astra defaults, structured result schemas, bounded response allowances, API parameter compatibility, and shared Director/Storyboard reasoning instructions. Preserve explicit environment overrides and existing provider preference. Direct OpenAI and Atlas use Responses with High reasoning and strict JSON schemas; Fal's text/vision OpenRouter routes expose provider-default reasoning and require local Ajv validation. Validate all providers locally. Do not send unsupported effort/schema/sampling parameters or silently substitute another model.
- Keep Newt Economy and Smart Text routing independent from Director/Storyboard intelligence. Image-model choice, resolution and fidelity do not change with an LLM upgrade.
- Enable Fal router reasoning for creative routes with `reasoning: true`; both false and the schema's omitted-field default disable it and reject models with mandatory reasoning. Keep output contracts and local validation intact. Strip only explicitly delimited leading reasoning blocks before validating the final answer; reject reasoning-only or incomplete results. Director stores the active action while running/failed and shows stage-specific progress or an accessible error above Scene Setup. Surface provider error details, preserve existing content, reject empty successful responses, and offer only explicit, lock-respecting retries. No automatic paid replay after failure.
- Newest scene/revision instructions override stale drafts. Preserve unaffected sections and use local final assembly; do not add an LLM pass to changing output-only settings. Reject incomplete, refused, malformed, missing-field and inconsistent-count results before state replacement. Keep reported paid usage on rejected responses; unknown provider charges remain unknown.
- Director permits one targeted repair for structural shot-plan errors, then fails without replacing existing work. Editorial scale preferences remain soft. Reference analysis must match exact supplied tags, never assign another asset's description by array position.
- `server/creative-analysis-cache.js` reuses successful Director image analysis for 30 minutes in at most 40 in-memory entries. Fingerprints include image bytes, reference tag/type, instructions, provider/model and credential. A changed image at the same URL invalidates it. Never cache failures or charge cached/in-flight shared usage twice. Do not persist secrets or image bytes in the cache.
- `src/storyboardPlanValidation.js` preserves legacy Director CUT validation and shared duplicate-prompt/frame-number checks. New Storyboard plans use `storyboardPlanStructureIssues` for contiguous shot IDs and valid single/opening/transition/ending phases. Same-shot action progression is distinct from inter-shot coverage; do not force new compositions on locked-off action or matched opposing speakers. Keep the old planning endpoint for legacy clients, but new clients use `storyboard-plan-v2` and `storyboardWorkflowV2` in health.
- A failed Storyboard planner preserves the existing frames, images and analysis, never substitutes generic fallback boards. Unavailable QC is explicitly unreviewed (`qcReviewStatus`), not passed, and cannot trigger a paid retry or become an approved continuity anchor. Preserve legacy frames lacking that field.
- Fal Storyboard LLM requests use `server/storyboard-fal.js` with a single paid submission. After an acknowledged request, a transport failure while polling or reading its result permits up to three delayed read-only reconnections to that same request ID and captured credential. Never resubmit, cancel the provider job, retry invalid output, or bypass explicit cancellation/timeouts. Exhausted connection failures report the request ID and possible billing, retain unknown usage in History, and preserve existing panels. Other providers and non-Storyboard routes are unchanged.
- Advanced's Quality Control selector defaults to Balanced for new nodes and legacy enabled QC; preserve explicit Off (`storyboardAutoQc: false`) and saved Deep (`storyboardQcMode`). `server/storyboard-qc.js` owns automatic review tiers and exact-result reuse. - Editor is an explicit/manual export surface, excluded from ordinary Run All and marked manual-only in Newt until agent editing tools are implemented. Keep timeline data and assets portable through save/import/presets; do not copy active export job ownership into duplicated/preset nodes. Test edits, locks, exact frame counts, actual rendered pixels/audio, playback, canvas focus isolation and save/reload. No live provider generations are needed.

## Output Delivery

- `output` appears immediately above Utility in every shared node menu. Its single gray `mediaIn` accepts images, video, audio, and ready Character/Mood Board media, including connections made before generation. It has no outgoing port and is excluded from Run All and Newt generation tools. Filesystem paths and Auto Export are not agent-editable.
- `src/outputNode.js` owns normalization, naming, selected/all resolution and receipts; `OutputNodeBody.jsx`, `useOutputExport.js`, and `outputNode.css` own the lazy-loaded UI and controller. Separate image/video/audio destinations remember their folder, optional relative subfolder and format. Original performs a byte-preserving raster/video/audio copy. Explicit image conversions are PNG/JPEG/WebP, SVG from a Vector companion, or alpha-matte PNG; video MP4/MOV H.264, and audio WAV/MP3. SVG delivery validates and serializes passive artwork before any render/write, never wraps a raster in SVG. Alpha is extracted locally from the canonical image, white opaque/black transparent. Retain canonical identity separately so SVG companion selection cannot cause repeat auto-exports. Never resize silently, modify source assets or replace canonical project media with external delivery paths.
- Name modes are Original, Project, Source Node and Custom, with optional numbered filenames. Existing files are never overwritten: number new copies by default or explicitly skip. All exports current completed results, not historical versions; Storyboard All exports individual panels, while Selected can export the current compiled board. Respect port-specific Character sheet selection and current Editor exports.
- Export is manual by default. Auto Export is explicit opt-in; record ownership before submission, export newly ready results once, and pause on settings changes, partial failure, cancellation or uncertainty. Remount/reopen may poll a saved job but must never resubmit it. Duplicated or preset nodes retain configuration but clear receipts/jobs and disable Auto Export. Use bounded saved receipts and a cumulative media identity baseline to prevent rerender/reconnect loops.
- `server/routes/output.js` and `server/output-export.js` implement validation, asynchronous idempotent exports, read-only status, cancellation and receipt-scoped Reveal. Resolve only managed uploads/outputs/registered workflow media with the dedicated read-only resolver, never the general repair/download resolver. Validate actual file signatures and stream types using Sharp/FFprobe, restrict paths and symlinks, and use argument arrays for FFmpeg. At most 100 files per batch and two simultaneous exports. Keep successful files in partial batches and show actionable local errors. There are no paid API calls.
- The backend Reveal allowlist persists only bounded destination receipts under ignored `server/data/output-receipts.json`, with file/directory identity checks. A backend restart does not recreate jobs or replay exports. Missing jobs produce an unconfirmed status and direct the user to check the saved destination. Folder dialogs wait for explicit confirmation or cancellation without a UI deadline.
- Verify shared defaults/connections/save/copy with `test/outputNode.test.js`, controller lifecycle with `test/outputNodeController.test.js`, actual local copies/conversions/security with `test/outputExport.test.js`, and UI behavior with the isolated mocked `test/browser/output.html` harness. `outputExport` is required in API health and smoke checks.

## Audio Model

- Eleven v4 (`eleven_v4`) is a Text to Speech choice only; keep Multilingual v2 as the creation default and preserve saved model/voice choices. Submit literal text/audio tags (up to 10,000 characters) to `/v1/text-to-speech/:voice_id` with only Stability and Similarity voice settings. Hide unsupported Style, Speed and Speaker boost controls without discarding their saved values. Speech to Speech, Sound Effects and Music retain their own models. Reject unsupported explicit request models before paid work. The browser checks `routes.elevenLabsV4` before a v4 POST so an older backend cannot silently substitute Multilingual v2.
- v4 estimates use its separate standard API rate ($0.08/1K characters, verified 2026-10-06), excluding temporary promotions, with an optional `ELEVENLABS_V4_PER_1000_CHARACTERS_USD` override. Never borrow another model's rate when v4 pricing is missing. Official contract: https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech and https://elevenlabs.io/docs/overview/models; pricing: https://elevenlabs.io/pricing/api.
- `src/audioModel.js` owns the four modes, model IDs, defaults, normalization, parameter validation, and published fallback estimates. `audioModel` has yellow `promptIn`, orange `audioIn`, and orange `audioOut`. Only Speech to Speech uses audioIn; other modes use promptIn. Inactive edges stay saved but cannot influence execution. Audio input is single-source.
- `AudioModelNodeBody.jsx` owns controls and account voice loading. Group the fully paginated account voice list into Default and Mine; preserve the saved voice ID across key changes and require explicit reselection when unavailable. Refresh on provider changes. Do not send account credentials to the node or store voice catalogs in projects.
- `server/elevenlabs.js` and `server/routes/audioModel.js` use the enabled ElevenLabs key only, captured for the whole request. Use fixed ElevenLabs endpoints, bounded response sizes, and timeouts. Validate speech recordings locally before paid submission. Speech conversion is multipart, voice settings are JSON within that form, and music prompt requests never include seed. Never automatically retry a paid POST on either frontend or backend.
- `nodeRunners/audioModels.js` submits only the model fields and standard workflow context. Run batches sequentially through shared runner helpers, preserve previous results, retain partial successes, and chime once per completed node. Store canonical audio result items and managed MP3 outputs. Preview, the output rail, workflow import/copy/reopen, History, and Stats must retain audio types and all results.
- Published estimates are shared by the button and backend History. Record estimated costs at generation time; unknown auto duration/custom voice rates stay unknown, not zero. ElevenLabs pricing is not yet auto-refreshed by the weekly catalog. Newt marks audioModel manual-only until dedicated audio permissions, request journaling, and budget reservation are implemented; never bypass the agent's paid-request scope.
- `test/audioModel.test.js` and `test/elevenlabs.test.js` cover key versions, parameter contracts, voices/pagination, mode controls, batching, output preservation, pricing, and readable failures with mocked providers. Do not spend live provider funds in automated tests.

## Explore

- `src/explore.js` owns defaults, reference roles, bounded requests, prompt rules and canonical result selection. `ExploreNodeBody.jsx` is lazy-loaded; `nodeRunners/explore.js` runs one structured art-direction plan followed by sequential image requests through the existing image adapter. Defaults are nine directions and one image each, Flare Medium, 2K, 16:9, with normal enabled-model fallback only on fresh creation.
- Preserve medium-specific craft: cinematic/editorial photographic work, clean graphic language for logos. Separate product/character identity from mood/look references. Limit requests to eight references including parents, and one image per direction (up to 25). Ignore legacy variation multipliers for new runs, but retain unfinished legacy queues with their original counts. New batches carry only a bounded summary of earlier concepts. More Like This reuses saved direction text without an LLM call; Push Further, Refine and Combine make an explicit new plan.
- Explore Mode defaults on; off requests restrained execution without altering explicit style/grade choices. Style Family keeps Auto and adds Random; Grade keeps None and adds Random. Resolve random choices locally once per new batch/Push Further, balancing presets before reuse and excluding content-altering novelty styles. Graphic tasks use graphic random families. Send the same ordered choices to planning and each image request, persist resolved choices per result/queue, and retain them on Resume and More Like This/Refine. Connected Image / Product references lock scene content, framing, subject count, identity, wardrobe and layout unless the brief explicitly requests a change; style presets, range and Explore Mode never override this. Mood Board references remain look-only. Version 2 planning requires the `exploreLookVariation` health flag so a stale backend cannot silently discard these controls. Existing queue snapshots remain usable without rerolling looks or adding new content rules retroactively.
- Version 3 also requires `exploreArtDirection` before planning. `src/exploreArtDirection.js` owns Explore-only broad medium definitions and bounded, locally assigned multi-axis contrast briefs. Preserve shared Style presets elsewhere. With Explore Mode on, new exploration/Push receives contrasting camera, composition, lighting, palette, art direction and texture strategies; fixed-image references receive only lighting/palette/texture/tonal strategies, graphic tasks use graphic projection, and explicit Camera/Grade/monochrome constraints override conflicting suggestions. Rotate distinct combinations through 25 directions; pass and validate the same numeric assignments through the route, queue and result metadata without rerolling. The planner invents coherent brief-specific concepts and silently compares their distinctness in its single response. At default range 55, aim for visibly different directions across four unconstrained dimensions, not slight hue/seed changes. Explicit subject/identity/branding constraints always win. Do not add an LLM judge, paid repair or hidden generations. Include all planned concept/composition/lighting/palette/treatment fields in each final image prompt, not just its summary prompt. Off retains original restrained preset guidance. More/Refine/Combine receive no fresh contrast assignments; pre-v3 queued prompts retain their original generation behavior. Keep previous-direction visual summaries bounded to 400 characters each. Test with `test/exploreArtDirection.test.js` and `scripts/verifyExploreArtDirection.mjs`; mocked tests verify instructions and state, not live visual quality.
- Grade replaces Variations / Direction and uses shared `colorLook.js` named presets (None by default). Send it to both planner and image prompts, preserve brand/subject colors, and include the image's saved grade in its direction details. Reference descriptions live in their own collapsible section, closed on mount even for saved nodes. Expansion is local UI state, not a project edit; discard legacy `referencesOpen` during normalization. `CollapsedInputPorts` retains measurable `data-port-key` anchors for each remaining typed edge at one gray dot, never an ambiguous drop target. Expanding restores individual ports without editing edges.
- Persist every successful result, selected index, saved style description, direction lineage and queue snapshot. Respect upstream reference locks. Preserve files and History when removing a result from the gallery.
- Display results in a horizontal thumbnail strip without a large empty viewer. `imageOut` is Explore's only output: Preview receives all full-resolution images with direction labels, while other image consumers receive the selected result. Style Family/Grade in Settings replace the Style input; keep Brief, Image / Product, Character, Camera and Mood Board inputs. The removed `styleIn`, `styleOut`/`promptOut` ports and Advanced Outputs section must not reappear; graph normalization drops their obsolete edges on restore/import/paste, and node normalization discards `advancedOutputsOpen` without losing media or details. New canvas runs do not read connected Style guidance, while saved queues retain their snapshotted prompts. Saved style descriptions remain internal and never leak into downstream prompts through an image connection. This UI/input cleanup requires no backend restart.
- Stop finishes the current submitted request and leaves remaining entries pending. Resume submits only pending/failed entries with their original plan, references and settings, after checking those models/formats remain enabled. Interrupted entries become uncertain on restoration; no automatic resubmission or cancellation. A partial or paused batch blocks downstream Run All. Chime only when the whole requested batch completes.
- `/api/node/explore-plan` uses the shared OpenAI creative model routing and strict schema validation; record planning usage in History, including paid malformed responses. Cap concurrent plans at two and never replay an uncertain planning POST. Images reuse managed outputs and generation pricing. Show variable total cost when planning cost is not known; honor the workspace cost-visibility toggle. Explore is manual-only in Newt until approval, nested billing and request journaling support it.
- Fal Explore text/vision prompts include the canonical JSON schema in their system instructions because that adapter does not send a provider-enforced schema parameter. All providers require the same eight string fields per direction. Before strict validation, locally discard unused response metadata and join nonempty string-only palette lists into one string. Never invent missing fields, stringify palette objects, truncate oversized plans, accept partial/refused replies or issue a paid repair/retry. Forward the normalized JSON through both adapters and the route; preserve assigned request-side looks, existing results, queue state and billed-usage recording on failure. Other creative routes retain their existing strict behavior.
- Verify with `test/explore.test.js` and the isolated mocked `test/browser/explore.html` harness. Live provider spending is not necessary for regression tests. See `docs/explore-node.md` for the interaction and maintenance guide.
