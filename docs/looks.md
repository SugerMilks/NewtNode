# Looks Integration

## Source and Scope

The compact catalog reader in `server/looks-catalog.js` is adapted from `server/stylefinder-compact.js` in [kungfukoi/Newt_Node at ca96ee494f3197ea871d6c33e50fb8f7a7b133fa](https://github.com/kungfukoi/Newt_Node/blob/ca96ee494f3197ea871d6c33e50fb8f7a7b133fa/server/stylefinder-compact.js), inspected November 10, 2026. The model-neutral style snapshot and handoff follow the same Lookbook design. This is a scoped integration requested for the collaborating NewtNode versions, not a merge of the upstream application.

The local version adds a lazily loaded Looks workspace, searchable paginated gallery, categories, persistent favorites, full-image inspection, editable descriptions, and insertion into the active project's active canvas. The existing editor remains mounted across tabs. Style output carries rendering instructions; Mood Board uses local visual references with the existing compile/lock workflow. No automatic model calls, website crawling, new provider, source-file retirement, external synchronization or upstream Timeline/UI changes are included.

## Data and Safety

- Configure an absolute directory containing a version-1 compact `catalog.json` and `images` folder. A parent containing a `Looks` child is also accepted. Do not hardcode personal paths or ship catalog contents.
- Settings and favorites live in ignored `server/data/looks`; cached 600px thumbnails live below its `thumbnails` directory. Source metadata is cached by path, modification time and size. Search is paginated, limited to 96 results per request, and never sends the complete manifest to the browser.
- Examples retain the upstream `/api/style-library/stylefinder-image` URL contract. Only manifest-listed, content-addressed JPEG/PNG/WebP assets inside the selected root may resolve. Reject traversal, stale versions, external fetch URLs, escaping symlinks and overlarge inputs. No catalog HTML or scripts execute.
- Imports validate image bytes and checksums, copy only the selected examples into `uploads/looks`, and return durable managed URLs. Identical assets reuse their hash-named copy. No source files are changed. A missing/disconnected catalog reports an actionable error while previously imported nodes keep working.
- `libraryStyle` snapshots contain a name, editable portable prompt, source attribution and managed examples. Normal project asset collection/rewrite includes these URLs when saving packages. Browser code may not put live catalog image URLs in node data.
- Add Style explicitly calls `/api/looks/create-style`. `server/looks-analysis.js` sends every available example (up to eight; normally four) as a separate whole-image reference in one vision call. The first example alone is not the style source. Catalog text is comparison context, never instructions. The shared adapter/schema validates completeness and records billed success/failure in History; no automatic repair or paid resubmission occurs. Successful analyses are cached locally by ordered source-image hashes, description and instruction version, and concurrent identical requests share the result. Cache-read errors stop before paid work. Add Mood Board retains the existing local-only import route.
- Analysis v2 examines all images but chooses one visually evidenced reference-led feature instead of averaging competing looks. The required `anchorReference` identifies a supplied image; `signatureFeature` describes concrete blocking, shape relationships, negative space, staging or rendering and is prepended to the editable saved prompt. Supporting qualities from the set must be compatible with it. Both text fields are instructed to exclude literal colors, hues, palettes, tint, saturation, color temperature and monochrome treatment; a final instruction check happens within the same request. This is prompt guidance, not a guarantee of model compliance. No extra judge/repair calls or color-word replacement heuristics are used. Versioned caching prevents v1 analyses from being reused for new Add Style actions without deleting earlier files or rewriting saved nodes.
- Style instructions separate transferable visual relationships from reference subjects, wardrobe, props, text, setting and contact-sheet layouts. Authored subject count, camera and composition take precedence. New look nodes default to Style None plus Custom Grade using the first image and locally extracted colors. A chosen preset stays separate from the look prompt and controls the medium; Grade controls color. The final prompt explicitly ignores color directives in the catalog look, including older saved descriptions; Grade None does not revive the catalog palette. Keep the editable prompt and full-resolution draggable thumbnails below the grade. Dragging any thumbnail to Custom Grade replaces only its image/colors using the normal extraction and undo flow, without reanalysis. Midjourney switches are stripped; no unsupported provider parameters are sent.
- `src/palettePixels.js` shares the dominant-color bucketing used by browser and server extraction. `gradeColors` is only handoff data; saved nodes retain the existing custom palette fields and portable look snapshot. Existing nodes keep their saved grades and prompts, with no automatic paid migration.
- Style Grade keeps Custom for image extraction and Precise Color for the manual spectrum, hue, eyedropper and swatch controls, without a thumbnail. Each mode retains its own palette when switching or clearing; only the selected mode affects generation. Old image-free hand-picked Custom palettes migrate locally to Precise Color without changing their grade prompt. Saved Precise Color Picker selections retain their colors under the shorter name. Looks imports and thumbnail dragging continue to target Custom.
- New API routes reject requests from non-local browser origins. The `looksLibrary` health capability gates the library; `looksStyleAnalysis` additionally gates Add Style so an older running backend prompts a restart before any paid request.

## Verification

- `node --test test/looks.test.js test/looksAnalysis.test.js test/looksIntegration.test.js test/workspaceNavigation.test.js`
- `LOOKS_QA_CATALOG=/absolute/path/to/Looks PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node scripts/verifyLooks.mjs`
- `npm test`, `npm run build`, `npm run bundle:report`, `npm run smoke:app`

Browser verification uses an isolated browser project and temporary backend storage. All non-Looks APIs are mocked or blocked, the vision adapter is mocked, and source catalogs are read-only. Checks cover desktop/mobile layout, real thumbnails, search/filter/favorites/paging, preview boundaries, active-canvas insertion, four-image analysis payloads, first-image grade defaults, independent preset selection, native thumbnail-to-grade dragging, managed copies, persistence and preservation of existing project content. No paid generation quality claim is made.
