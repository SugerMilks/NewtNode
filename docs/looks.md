# Looks Integration

## Source and Scope

The compact catalog reader in `server/looks-catalog.js` is adapted from `server/stylefinder-compact.js` in [kungfukoi/Newt_Node at ca96ee494f3197ea871d6c33e50fb8f7a7b133fa](https://github.com/kungfukoi/Newt_Node/blob/ca96ee494f3197ea871d6c33e50fb8f7a7b133fa/server/stylefinder-compact.js), inspected November 10, 2026. The model-neutral style snapshot and handoff follow the same Lookbook design. This is a scoped integration requested for the collaborating NewtNode versions, not a merge of the upstream application.

The local version adds a lazily loaded Looks workspace, continuously loaded gallery, categories, persistent favorites, full-image inspection, editable descriptions, and insertion into the active project's active canvas. The existing editor remains mounted across tabs. Style output carries rendering instructions; Mood Board uses local visual references with the existing compile/lock workflow. No automatic model calls, website crawling, new provider, source-file retirement, external synchronization or upstream Timeline/UI changes are included.

A second UI comparison against [upstream 98bee5551932da7b9ecf7c37e7c548c6cf1fa2e6](https://github.com/kungfukoi/Newt_Node/tree/98bee5551932da7b9ecf7c37e7c548c6cf1fa2e6) reviewed `src/LibraryWorkspace.jsx`, `src/components/LookbookShuttle.jsx` and `src/components/CreateLookDialog.jsx`. The local UI includes a horizontal image strip, checkbox multi-selection, local collections and Create Look. `LookShuttle.jsx` adapts the upstream velocity-based pointer/keyboard shuttle, with release/cancel/blur/hidden-tab cleanup. This adapts those workflows to existing local storage and analysis rather than copying shared-folder mutations or palette-mixing prompts.

## Data and Safety

- All Looks combines the connected catalog, My Looks and Shared User Looks. Search, category filters and Favorites apply across that combined set; Catalog, My Looks, Shared User Looks and collections explicitly narrow the scope. Existing favorite IDs remain unchanged. The server pages across source boundaries in stable catalog/local/shared order, returning at most 96 results, combined counts and the union of categories without sending the whole catalog to the browser. Unconnected sources are omitted quietly; unavailable or invalid connected sources produce a partial-results notice while available looks remain searchable. No settings, favorites or original files are rewritten. `looksUnifiedSearch` prevents an older backend from silently treating All Looks as catalog-only.
- Unfiltered All Looks opens at a random section on the first visit and when returning to the workspace. The client reads a bounded batch to learn the count, then fetches the chosen section directly, avoiding an immediate repeat where possible. The lazy strip continues from there, wraps to the earlier section once, and stops when all looks have been visited. It never shuffles during a visit or rewrites catalog order. Searches, categories, favorites, collections, My Looks and Shared User Looks retain normal ordering; returning with checked looks or an open dialog preserves the in-progress task. Failures retain the current start and images for explicit retry. No AI calls or backend update are involved.
- The detail dialog omits About this look and the Source link while retaining their metadata in the catalog and portable snapshots. One yellow Transfer Look button reveals a smoothly expanding panel with Text, Mood Board, Unique Style and Grade switches, initially off, and Apply Nodes. Honor reduced motion and remove collapsed controls from keyboard navigation. Text copies the exact current description, including edits and whitespace, into a normal Text node named after the look; blank descriptions disable it. It makes no API calls, copies no images and does not modify the saved look or reprocess the prompt.
- `src/lookTransfer.js` prepares all selected items before one canvas handoff. Text and Mood Board create their existing node types. Unique Style creates a Style node with Style None, the analyzed/saved prompt and Grade None unless Grade is also selected. Grade alone creates a Style node with Style None, Custom Grade from the first image, and all managed thumbnails in a prompt-free `libraryGrade` snapshot. It uses the existing local import and browser palette extraction, not AI. Selecting Unique Style and Grade combines them in one Style node. Import/analyze images once per batch, never retry paid work automatically, and preserve choices/description on failure without partial canvas insertion. Place nodes without overlap on the active canvas and record one undo operation for the batch. Reference choices remain draggable onto Custom Grade, including after project reload and asset packaging.
- Configure an absolute directory containing a version-1 compact `catalog.json` and `images` folder. A parent containing a `Looks` child is also accepted. Do not hardcode personal paths or ship catalog contents.
- Settings and favorites live in ignored `server/data/looks`; cached 600px thumbnails live below its `thumbnails` directory. Source metadata is cached by path, modification time and size. Search is paginated, limited to 96 results per request, and never sends the complete manifest to the browser.
- The UI has no page controls. `useLooksFeed.js` requests 48 entries at a time as the strip approaches its loaded end, preserving scroll position and selected IDs. Single-flight requests, abortable filter sessions, ID deduplication and explicit retry prevent duplicates, stale mixed results and request loops. `LookGallery.jsx` renders visible columns plus a small overscan window while retaining loaded metadata; scrolling backward restores those cards without refetching. Select Visible affects only the current viewport. Pointer, keyboard and wheel navigation work across batch boundaries. Random discovery wraps once to visit the earlier section, then stops; ordinary filtered feeds stop at their real end. Neither makes paid calls.
- Examples retain the upstream `/api/style-library/stylefinder-image` URL contract. Only manifest-listed, content-addressed JPEG/PNG/WebP assets inside the selected root may resolve. Reject traversal, stale versions, external fetch URLs, escaping symlinks and overlarge inputs. No catalog HTML or scripts execute.
- Imports validate image bytes and checksums, copy only the selected examples into `uploads/looks`, and return durable managed URLs. Identical assets reuse their hash-named copy. No source files are changed. A missing/disconnected catalog reports an actionable error while previously imported nodes keep working.
- `libraryStyle` snapshots contain a name, editable portable prompt, source attribution and managed examples. Normal project asset collection/rewrite includes these URLs when saving packages. Browser code may not put live catalog image URLs in node data.
- Selecting Unique Style and applying explicitly calls `/api/looks/create-style`. `server/looks-analysis.js` sends every available example (up to eight; normally four) as a separate whole-image reference in one vision call. The first example alone is not the style source. Catalog text is comparison context, never instructions. The shared adapter/schema validates completeness and records billed success/failure in History; no automatic repair or paid resubmission occurs. Successful analyses are cached locally by ordered source-image hashes, description and instruction version, and concurrent identical requests share the result. Cache-read errors stop before paid work. Mood Board retains the existing local-only import route when Unique Style is not selected.
- Analysis v2 examines all images but chooses one visually evidenced reference-led feature instead of averaging competing looks. The required `anchorReference` identifies a supplied image; `signatureFeature` describes concrete blocking, shape relationships, negative space, staging or rendering and is prepended to the editable saved prompt. Supporting qualities from the set must be compatible with it. Both text fields are instructed to exclude literal colors, hues, palettes, tint, saturation, color temperature and monochrome treatment; a final instruction check happens within the same request. This is prompt guidance, not a guarantee of model compliance. No extra judge/repair calls or color-word replacement heuristics are used. Versioned caching prevents v1 analyses from being reused for new Add Style actions without deleting earlier files or rewriting saved nodes.
- Style instructions separate transferable visual relationships from reference subjects, wardrobe, props, text, setting and contact-sheet layouts. Authored subject count, camera and composition take precedence. New look nodes default to Style None; selecting Grade also sets Custom Grade using the first image and locally extracted colors. Legacy Style handoffs retain their first-image Grade behavior. A chosen preset stays separate from the look prompt and controls the medium; Grade controls color. The final prompt explicitly ignores color directives in the catalog look, including older saved descriptions; Grade None does not revive the catalog palette. Keep the editable prompt and full-resolution draggable thumbnails below the grade; grade-only transfers have thumbnails but no style text. Dragging any thumbnail to Custom Grade replaces only its image/colors using the normal extraction and undo flow, without reanalysis. Midjourney switches are stripped; no unsupported provider parameters are sent.
- `src/palettePixels.js` shares the dominant-color bucketing used by browser and server extraction. `gradeColors` is only handoff data; saved nodes retain the existing custom palette fields and portable look snapshot. Existing nodes keep their saved grades and prompts, with no automatic paid migration.
- Style Grade keeps Custom for image extraction and Precise Color for the manual spectrum, hue, eyedropper and swatch controls, without a thumbnail. Each mode retains its own palette when switching or clearing; only the selected mode affects generation. Old image-free hand-picked Custom palettes migrate locally to Precise Color without changing their grade prompt. Saved Precise Color Picker selections retain their colors under the shorter name. Looks imports and thumbnail dragging continue to target Custom.
- New API routes reject requests from non-local browser origins. The `looksLibrary` health capability gates the library; `looksStyleAnalysis` additionally gates Add Style so an older running backend prompts a restart before any paid request.
- `looksWorkspaceTools` gates custom Looks and collections. `server/looks-user-library.js` atomically stores up to 500 created looks and 100 collections in ignored `server/data/looks/user-library.json`. Collections contain at most 500 IDs, not duplicate image data. Only created looks may be deleted; deletion removes library membership but keeps managed images for existing projects. Catalog originals are always read-only. A corrupt library is preserved and reported, never reset on write.
- New Create Look dialogs accept one to six managed still PNG/JPEG/WebP/AVIF references, each bounded to 16 MB and 40 million pixels, matching the peer. Existing eight-image/32 MB local looks remain readable. Validate all before analysis or library creation, copy content-addressed images into ignored `uploads/looks`, preserve their order, and use a stable client-generated ID to make identical saves idempotent; edits establish a new identity. Local created looks can be browsed/reused without a connected source catalog.
- Extract Style is an explicit optional AI action with its own six-section schema, instructions and versioned cache, separate from catalog Add Style. It uses all references in one high-reasoning vision request through the existing configured provider. It returns a short description, medium/rendering, lighting/contrast, texture/detail, shape/edges, depth/atmosphere, mood/character, category tags, and a separate palette. All style text excludes reference subjects and literal colors. Users may instead write a description or sections themselves. Saving, reordering references, creating collections and reusing a saved custom description do not call AI. The first image still supplies Custom Grade and Style still defaults to None. No paid calls were made during verification.

Desktop/mobile checks cover section editing, exclusions, priority changes, separate color editing, prompt preview, a reachable Save button, reload and shared transfer. ## Shared User Looks Compatibility

Compared against [kungfukoi/Newt_Node commit 41613cebdf4d4f544558ad1da233d2c6cb9fb2b0](https://github.com/kungfukoi/Newt_Node/tree/41613cebdf4d4f544558ad1da233d2c6cb9fb2b0) on November 10, 2026. This is shared-file compatibility, not an identical application or UI merge.

| Feature | Compatibility / deliberate difference |
| --- | --- |
| Compact image catalog | Same version-1 `catalog.json` and hash-addressed images. Read-only here. |
| Gallery, shuttle, selection, favorites, collections | Equivalent core actions; our bounded continuous gallery and private collections are retained. |
| Create Look / reuse | Same six-image extraction and six-section style board, priorities, tags and separate palette; manual-description/no-AI creation remains available here. |
| Shared User Looks | Same version-1 `look-<uuid>/look.json` plus `images/<sha256>.<ext>`; reads dedicated and legacy nested `looks` layouts. |
| Shared removal | Same `deleted.json` marker. Explicit confirmation warns it affects everyone; image files and existing node copies remain. |
| Rich style metadata | Creation now has the six-section priority editor; sections, palette and notes remain in shared records. Existing Look inspection retains the editable compiled description. |
| Style / Grade / Mood Board | Keep our color-neutral, signature-feature logic, Style None, first-image Custom Grade and thumbnail replacement. Mood Board is unchanged. |
| Remote catalogs / cleanup | No StyleRef crawling, source-image retirement, automatic migration or collection synchronization added. |

In Looks, open the folder icon and set **Shared User Looks** to the same mounted/synced folder your collaborator uses. Their setting is named **Shared User Looks** too. Each machine can have a different absolute mount path, provided both point to the same contents. Keep the large catalog in the separate **Catalog folder** field. The app does not install or manage a synchronization service.

Connecting does not publish existing looks. Select local/catalog looks and click **Share** to copy them explicitly; originals stay local. New Create Look dialogs default to the shared destination while it is connected, with **My Looks** still selectable. **Shared User Looks** appears in the library selector. Refresh to pick up changes from the other machine. Favorites and collection memberships are private. Sharing supports up to six still PNG/JPEG/WebP/AVIF images, 16 MB each, and descriptions up to 6,000 characters; oversized legacy local looks fail clearly rather than being truncated. New dialogs use the same image limits for either destination.

`server/looks-shared.js` owns relative records, SHA-256 verification, immutable identities, atomic per-look publication and deletion markers. Settings stay in ignored `server/data/looks/shared-folder.json`. Reads reject malformed versions, changed checksums, escaping paths and nested symlinks. No data is written into the compact catalog. Missing mounts never receive automatic local fallback saves; conflicts do not overwrite the other user's look. Shared images are copied into managed `uploads/looks` before node creation, so saved projects do not depend on the drive remaining connected. Imported saved descriptions never trigger new AI analysis. An authored description is represented as authored metadata, not a claimed AI analysis.

The opt-in test below loads the actual upstream storage module from a separate checkout, exchanges test records in both directions, checks image bytes/order and verifies deletion compatibility. It uses synthetic images only, not the user's catalog, shared folder or paid providers:

```sh
UPSTREAM_LOOKS_ROOT=/path/to/kungfukoi-checkout node --test test/looksShared.test.js
```

This verifies the inspected version's file contract. It does not establish behavior of future upstream changes or network-drive synchronization timing.

## Film Stills

Place palette-sheet images in `FilmColorStills` inside the connected catalog folder. **Film Stills** appears in the library selector and is also included in All Looks, search, Favorites and collections. The first index runs locally; subsequent visits reuse derived images. Originals are read-only and all derived data stays in ignored `server/data/looks/film-stills`. No catalog images or palette data belong in Git.

Film Still names are display-only: `server/film-still-names.js` spaces readable filename labels and adds a color/tone description from the hand-picked palette. Numeric/generic names and ambiguous initials receive a descriptive look name instead of a guessed film title. These are local tonal descriptions, not AI scene recognition or verified film attribution. Existing cached stills receive names without re-extraction; IDs, image hashes, palettes, favorites and collections stay unchanged. Original filename stems remain searchable. New canvas transfers and shared copies use the readable names; existing canvas snapshots and shared records are not silently renamed.

`server/film-stills.js` recognizes the supplied layout: a white-bordered still above a white separator and a row of 10-24 flat vertical color swatches. It validates borders, swatch dimensions and color consistency before cropping. Unsupported/uncertain layouts and pictures without palettes are skipped, not guessed. Raster bytes are decoded independently of filename extensions, oriented and converted to sRGB. Sampling inside the swatches avoids white separators and compression edges. If more than ten distinct swatches exist, rank those supplied colors by nearest perceptual-color coverage within the clean still and retain the ten strongest in original swatch order. Never generate replacement colors or sample a new palette from the picture. Damaged derived images can be rebuilt from their originals without AI.

Each example carries `filmStillPalette: { version: 1, colors: [ten HEX values] }`. Transfer Look -> Grade copies only the clean PNG into managed uploads and seeds Custom Grade from that exact palette. Unique Style remains independent; combining them still creates one Style node. Clicking or dragging a reference thumbnail replaces its clean still and all ten colors atomically, including after undo, reload and project packaging. Pending ordinary-image extraction cannot overwrite a later Film Still selection. Ordinary references retain existing palette extraction.

`src/filmStillGrade.js` owns validation, pairing and the grade-only prompt. Image Model and custom-style Storyboard generation receive the clean image with a color/tone-only label and all ten explicit HEX values. Treat those values as non-rendered grading data for natural tonal relationships, not a requirement to visibly display each color or limit the picture to ten flat colors. Explicitly forbid adding swatch strips, charts, HEX/RGB labels, legends, borders or margins from the grading data while allowing text/graphics requested by the user. Their content, camera and framing remain authoritative; the reference must not introduce its actors, props, set or palette layout. The default monochrome Storyboard mode does not receive the color reference. Turning Grade off stops its prompt and image reference together. Model compliance remains generative, not exact color-management enforcement. No paid generation was used to verify this feature.

Shared version-1 manifests carry the palette on each image, alongside the clean image file; the first palette is also present in ordinary `look.colours` for older readers. No machine-local source paths are required. The inspected peer reader accepts these files, clean images and fallback colors. Automatic per-image palette switching requires the Film Stills update on both apps; an older app may discard the extra metadata if it rewrites the Look. Connecting a shared folder alone never publishes the source collection.

The November 12 local-folder audit accepted 545 palette sheets and skipped six still-only files. Verification includes representative clean-crop inspection, all source-sheet detection, synthetic no-palette/unsafe-path tests, actual peer reads and browser click/drag/undo/reload tests. `looksFilmStills` health guards the new backend operations.
