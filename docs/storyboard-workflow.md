# Storyboard Workflow

## PDF Script Import

Storyboard Setup includes a compact **Import Script PDF** button. Choose a PDF and Newt detects its script, builds the shot list, and adds the editable rows directly to the node. If it finds multiple scripts or versions, choose one from a single dropdown and import continues automatically. No image generation starts during import.

- The reader preserves text positions for AV columns and screenplay indentation. Image-heavy/scanned pages use billed visual transcription; script discovery and shot-list drafting use the existing enabled creative LLM provider. The import action's tooltip discloses provider charges. Imported documents are untrusted source material, never instructions to the agent.
- Discovery keeps page numbers, formats, excerpts and scene boundaries in the background. A single script is chosen automatically; alternate spots/versions stay separate and require a choice. The whole chosen script is imported, not a manual page/scene selection. Treatment look pages and unrelated deck material are excluded from shot building.
- The script is limited to **50 pages**, with extra-time/cost confirmation for **31-50** only when needed. These are script pages, not total deck pages. Local safety bounds remain 40 MB / 200 document pages, 260,000 characters per analysis, and at most 50 scanned pages per analysis. Larger/unclear documents need a shorter or clearer script PDF; nothing is silently truncated. Page references use PDF positions, not printed labels.
- Shot count is chosen automatically up to the existing 35-shot Storyboard limit, not a user setting. Each shot retains action, dialogue, voiceover, onscreen text, timing, production notes and source pages separately. A script requiring more shots must be shortened rather than silently losing beats.
- Completed shots appear directly in the normal Shot List editor. Existing shots are preserved and new shots append automatically when they fit; only an empty initial placeholder is discarded. If the combined list cannot fit, prepared shots remain available without a paid rebuild. Replacing existing shots requires confirmation and cannot remove protected shots. Saved media is never deleted. Then use **Plan Shots** for reference binding, cast/spatial continuity and final image prompts, followed by generation when ready. Other approaches remain unchanged unless an import is applied.
- Each imported shot keeps a collapsed Source detail with its original PDF link. Source PDFs and pending imports live in normal project data and travel with workflow packages. Dialogue and voiceover inform acting/timing, not visible lettering. Source details survive planning, image revisions and version history.
- No paid request is automatically retried or resumed on reopening. Failures retain current boards; successful and malformed LLM responses are recorded in History. Visual transcription is reused while its document remains in the small local memory cache; it may need a new billed read after restart. No provider-specific native PDF API is required.

Implementation: `src/storyboardScriptImport.js`, `src/components/StoryboardScriptImport.jsx`, `server/routes/storyboardScripts.js`, and a bounded PDF.js worker in `server/script-pdf-worker.js`. PDF import requires Node 22.13+ and the bundled PDF.js canvas dependency. Test with `test/storyboardScriptImport.test.js` and the isolated mocked `test/browser/storyboardScript.html` harness. Live model extraction quality has not been certified by the mocked tests; no production credits are used in automated tests.

## User Actions

- New Storyboards start in Shot List with one blank shot. Add up to 35 rows, describe each shot and select its framing, lens and angle; Auto lets the planner choose. Rows can be reordered, deleted, protected and previewed. Plan Shots enriches each row using the same professional continuity and reference logic, returning exactly one frame per row without changing explicit camera choices or adding coverage. Generate Missing or an individual Run then renders the planned directions.
- Shot List keeps optional Scene Context in a disclosure instead of requiring a scene summary. Row edits require Plan Shots before generation; existing images and versions remain until explicitly regenerated successfully. Full planning requires unprotected rows. Selected revisions and gallery prompt/camera edits remain available, and successful revisions update the corresponding authored row. Save/reopen preserves shot descriptions, camera choices and planning state.
- Setup keeps consistent controls on the left and a top-aligned, resizable Scene Description on the right, with compact Planning Notes below. At narrower node widths these stack vertically. Long descriptions scroll within the editor, with their @tag highlights following the same viewport. Connected Scene Text remains read-only; disconnecting restores the user's local description.
- Storyboard View opens as an image-first gallery. Each panel's pencil disclosure opens its camera controls, prompt, Run, protection, deletion and previous versions; only one panel editor is open at a time. Selection checkboxes stay on the thumbnails, and the batch revision field appears only when panels are selected. Scene-setup changes have a quiet information indicator; actual errors remain visible.
- The overall yellow lock has been removed. Completed panels automatically prepare the combined storyboard output locally after generation or changes settle, without an LLM or image-generation charge. Connect the blue output to Preview as before. Failed output assembly shows a Retry control without failing the generation or deleting any panels. Per-panel protection remains separate.
- The download icon offers Export Frames and Export PDF directly from completed panels, without requiring a compiled output first. Create New Plan is available in Setup, not alongside the finished gallery.
- Create New Plan builds a self-contained scene plan. Replacing an existing plan requires confirmation and cannot replace protected panels. Graph Undo can recover an accepted replacement in the current session.
- Generate Missing fills only unprotected panels with no image. It never replaces a completed board implicitly.
- Select panel checkboxes, enter an instruction, then Revise Selected to revise up to eight panels. Shot controls, cast blocking, notes and action states are revised together. Only successful replacements commit their new directions and images; failed panels retain the old version and show an error. The revision instruction and selection remain available for an explicit retry.
- Regenerate Selected creates new images from the current panel directions without a planning call. Individual Run buttons retain this behavior too.
- Protect prevents edits, generation, restoration and deletion of that panel. Reordering cannot move a panel across a protected panel. It does not lock the whole project against deletion or Undo.
- Previous versions retains up to eight prior images with the directions that produced them. Restore also keeps the displaced current version. Files are not deleted when the bounded UI history drops an entry.
- Review Sequence checks directions and, when available, a numbered contact sheet. Results are advisory; it never changes images or spends on follow-up generations automatically. Per-frame Quality Control is independently configurable in Advanced: Balanced (default), Deep, or Off. Explicitly disabled QC stays off when an old project is reopened.
- Balanced reviews every new panel with smaller review-only copies and the same configured LLM. Possible major failures and uncertain detail get one independent higher-detail confirmation. Only confirmed story/continuity/identity/physical/rendering failures can trigger the existing single automatic image retry; subtle performance and optional polish do not. Deep uses original full-resolution images and High reasoning in one pass. Off skips automatic visual review. Planning, image generation and original references retain their existing quality settings.
- Balanced accepts a readable emotional beat without demanding literal micro-expressions or exact acting intensity, even during confirmation. Deep retains closer scrutiny of explicit performance direction. Completed QC notes are available inside each frame's pencil/details disclosure; they no longer clutter the gallery. Generation errors remain visible.
- While a frame is rendering, select and edit other idle panels, adjust their camera/prompt, protect them, restore a previous version, edit their image, or draft the next selected revision. Active and queued frames remain protected from edits. Starting another paid run, exporting, adding/removing panels or reordering waits for the current run to finish. Incoming render results preserve other edits and the user's selection.

Scene text changes no longer block local revisions. Create New Plan remains an intentional reset for summary approaches. Connected Character sheets work with either standard monochrome or custom rendering through the Character input directly under Props in Setup. The uploaded-character section has been removed; older projects retain their saved character data and prepared sheets. Planning offers Shot List, Dialogue, Action, Commercial or Montage, plus pacing and an optional duration target. The latter four retain their summary workflows. Saved Narrative/missing approaches retain Standard and its summary editor until explicitly changed; no saved boards are automatically converted. Duration is directing guidance, not a rendered runtime guarantee.

## Maintenance

Skill 2.4.0 adds Camera Personality to the exact authored-shot planning introduced in 2.3.0, retaining the physical occupancy rules from 2.2.0. `src/storyboardShotList.js` validates count, IDs, order and explicit camera choices before accepting a plan, merges planned directions without replacing media, and tracks authored-row provenance through revisions and image versions. `StoryboardShotList.jsx` owns the row UI. Keep summary approaches independent of these constraints.

Camera Personality lives in Setup independently of Approach: Restrained favors controlled composition, Expressive (the default) adds motivated perspective and graphic framing, and Bold allows stronger distortion, viewpoints and Dutch angles when the story supports them. All three respect authored shot choices and continuity. PDF imports use the same policy when proposing shots. Camera fields and descriptive prompts travel together; Dutch Angle survives saved projects and revisions. Changing personality does not rewrite existing shots or regenerate images. Use it for subsequent planning or request a targeted cinematography revision. QC protects intentional optical exaggeration in both modes, without adding LLM calls or increasing image retries. The shared policy lives in `src/storyboardCinematography.js` so it can evolve alongside the versioned directing skill.

Rebinding preset assets retains authored shot descriptions/cameras with rewritten reference tags, but clears planned prompts and generated media so the new inputs are planned explicitly. Newt can plan/generate existing authored rows; its tools do not directly write frame arrays. For new summary-based agent tasks it must choose an appropriate summary approach instead of submitting an empty Shot List, and must not silently convert an existing authored list.
Planning and selected revisions resolve routine cast omissions automatically. After a structurally valid draft, cast and spatial validation can trigger at most one text-model correction for the affected panel numbers. It uses the scene, draft, continuity and neighboring panels to decide visible/offscreen staging; it never blindly marks everyone visible or offscreen. Cast, prompt, beat, notes and spatial occupancy/exclusions may be corrected. Unaffected panels, IDs, numbering, camera setup/view boundaries, physical blocking changes, timing and action states remain intact. The repaired result must pass validation before use. Both text calls are recorded in History and task cost; valid drafts need no additional call. Provider/schema failures are not replayed, and unresolved corrections still preserve existing boards. No extra image generation is added.

Skill 2.2.0 plans physical occupancy before shot focus. `src/storyboardSpatial.js` defines each panel's continuous space, camera setup, actual view, visible world places, present people/places, justified offscreen exclusions and real blocking changes. A listener cannot disappear from a seat still in view, or silently change visibility in a held/returning camera setup. True singles, inserts, reverses, occlusion, entrances/exits and location/time changes remain valid. The hidden records travel with directions, versions, saves and image prompts; manual prompt/camera edits invalidate hidden cast/spatial instructions together. Older panels without spatial records remain usable and are never automatically replanned. Selected revision checks include read-only surrounding panels. Per-frame visual QC and sequence review also inspect actual occupied space against prior/anchor images, rather than trusting an incorrect offscreen label. These checks improve planning and review; they are not a mathematical camera simulation or a guarantee of image-model compliance.

1. Edit `server/storyboard-skills/directing-v2.md` for directing judgment and reference/revision policy. Keep that file focused on creative behavior, not credentials or executable commands. It is read for each request.
2. Bump `storyboardSkillVersion` in `src/storyboardWorkflow.js` when changing policy. The version is stored with new plans and History and participates in reference-analysis cache identity. A breaking policy change should get a new skill filename too.
3. Change `src/storyboardWorkflow.js` for contracts and pure validation/versioning logic. Schemas are wired into the existing strict/local provider validation through `server/creative-llm.js`.
4. `server/routes/storyboard.js` owns planning, reference analysis, selected revision and advisory review. Keep usage recording on rejected provider outputs, duplicate-task guards, local-reference validation and bounded selections. Cached analysis lasts up to 30 minutes/40 entries and never bills cache hits again.
5. Existing `STORYBOARD_OPENAI_MODEL` and `STORYBOARD_FAL_MODEL` overrides remain supported. Change model defaults through the shared creative LLM configuration, not UI model selectors; image fidelity and planning intelligence are separate.
6. The editor owns media generation, per-frame QC, atomic successful replacement, stale-response checks, version restore and output invalidation. `useStoryboardBoardOutput.js` debounces local contact-sheet preparation, coalesces explicit Newt export requests, and guards project changes and stale results. Failed signatures require explicit Retry; they never auto-loop. Legacy compiled boards are retained. All current/previous managed media URLs are included by recursive workflow packaging. Internal frame export names are unique; user exports retain normal numbered names.
7. `server/storyboard-qc.js` owns bounded review tiers, decision gating and reuse of identical resolved reviews. Bump its policy version when changing decision/resize rules. Keep exact image bytes, reference labels, prompt/context, policy, mode, model and credentials in the cache key; never cache unreviewed results. In-memory reuse lasts at most 30 minutes and records no new charge. Record both review passes when needed, including invalid paid output; unknown costs stay unknown. Do not automatically replay a provider/schema failure. Balanced uses Low reasoning only where supported (OpenAI/Atlas); Fal's vision router retains its supported reasoning parameters. Smaller copies reduce input size but do not guarantee identical detection or a fixed percentage of dollar savings.

Existing saved boards are never automatically replanned. `storyboardMigration.js` copies inherited Director scene text and active references before removing the old control connection, retaining original input metadata in `storyboardLegacyDirector`. Director sources and existing rendered panels remain. Director-to-Video is unchanged. The legacy planning API remains available for older clients; current clients use `/api/node/storyboard-plan-v2`, `/storyboard-revise` and `/storyboard-review`.
